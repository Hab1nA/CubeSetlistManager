# 移动端遥控与翻谱自动化设计

> 状态：设计定稿，待实现。日期：2026-09-24。
> 网页排版参照 [suckyble/ReaSetlistManager](https://github.com/suckyble/ReaSetlistManager)
> （单 HTML + 轮询 + 底部大按钮走带条 + RESYNC 断线恢复的交互范式）。
> 全程本地通信，不依赖互联网。

## 一、目标与范围

1. **网页遥控**：本软件开启 Windows 移动热点，平板连热点后用浏览器访问控制页
   （播放列表、NOW/NEXT、走带控制，与桌面端同源同权）。
2. **翻谱自动化**：Cubase MIDI 轨经专用 loopMIDI 端口发翻谱信号，本软件解析后
   直接 HTTP 推送到平板自研 APP（Cube 翻谱），由无障碍手势在屏幕左/右半区做单击/双击/滑动，或发媒体键（蓝牙踏板兼容）完成翻页——按谱面 App 支持情况在网页选翻页方法。

已拍板的范围裁剪：

- **无 WiFi 网卡不做兼容**：检测不到无线网卡即报错并禁用该功能，不给降级路径。
- **翻页方式只做「区域单击/双击」**；模拟 PageUp/Down、左右方向键搁置
  （安卓禁止普通应用向其他应用注入按键，INJECT_EVENTS 属系统级权限）；滑动手势已随自研 APP 支持。

## 二、总体架构

```
平板浏览器 ──HTTP(轮询/命令)──► 内嵌 HTTP 服务（绑热点 IP）
                                   │ self.calls 队列回 Tk 主线程
                                   ▼
                              Cubase 走带 / 切歌 / 全停

Cubase MIDI 轨 ──loopMIDI 翻谱端口──► 专用输入线程（入队 + 组合窗口判组合）
                                   │ 合法组合
                                   ▼
                       逐设备 HTTP POST（平板 IP:翻谱接收端口）
                                   ▼
                       自研 APP 内嵌接收器（8766）→ 无障碍手势/媒体键 → 谱面 App 翻页

热点管理：PowerShell 子进程调 WinRT NetworkOperatorTetheringManager
```

- 新增模块 `web_remote.py`（HTTP 服务、设备表、翻谱推送），热点控制可并入或独立 `hotspot.py`。
- 翻谱数据路径**全程不经过浏览器**——这是后台稳定性（第八节）的架构前提。

## 三、热点管理

- 用 PowerShell 子进程调 WinRT `NetworkOperatorTetheringManager.StartTetheringAsync()`
  （脚本字符串内置在代码里，不新增分发文件）；旧式 `netsh wlan hostednetwork` 不用。
- 启用时序：查 WiFi 能力 → 无网卡 = 弹错误并保持功能关闭 → 开热点 → 读取
  SSID/密码/本机热点 IP → 启动 HTTP 服务并绑定该 IP → 设置页显示 SSID/密码/IP 供平板接入。
- 热点本机 IP 默认 `192.168.137.1`（ICS 默认网段），但**运行时从系统实际查询**，
  不硬编码地址；服务只绑热点网卡，不绑 0.0.0.0。
- 关闭时序反向：停 HTTP 服务 → StopTetheringAsync。
- 防火墙：首次监听 Windows 弹「允许访问」，一次性放行，写入使用注意。
- 已知坑：热点在无客户端一段时间后会被 Windows 自动关闭（演前检查表覆盖）；
  非管理员权限能否开热点待实测（多数环境可以）。

## 四、网页遥控端

- **单文件 HTML，内嵌 CSS/JS**（ReaSetlistManager 的选型：兼容旧平板、离线可用、零构建）。
- 布局：顶部 NOW 大字 + NEXT 次级；中部歌单列表（当前项高亮，歌名永不截断，显示时长）；
  底部 sticky 走带条，大触控目标：播放 / 暂停 / 继续 / 停止 / 回零 / 上一首 / 下一首 / 全停。
- 状态同步：**1 秒轮询**，不做 WebSocket；切歌是关开 .cpr 的秒级操作，期间禁用按钮并显示
  「切换中…」；页面带连接状态徽标，回前台（visibilitychange）立即全量刷新一次，仿 RESYNC。
- 接口（服务端口默认 8765，可配）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 页面本体 |
| GET | `/state` | 快照：NOW/NEXT/歌单/当前索引/切换中/走带状态 |
| POST | `/cmd` | `{action: play\|pause\|resume\|stop\|rewind\|next\|prev\|panic\|switch, index?}` |
| GET | `/devices` | 已配对翻谱设备列表（第六节） |
| POST | `/device/claim` | `{slot?, name, screen:{w,h}}` 认领槽位并上报分辨率 |
| POST | `/device/update` | `{name?, method?, enabled?}` 改名/改方法/设备开关 |
| POST | `/device/test` | `{dir: prev\|next}` 对本设备试发一次翻页（调试用） |

- 所有控制动作经既有 `self.calls` 队列回 Tk 主线程执行，复用 `_transport / _next / _prev /
  _panic / _switch`，不在 HTTP 线程碰 Tk；`/state` 数据复用 `_tick_banner` 的 NOW/NEXT 计算。
- 与桌面端一致的行为约束：切歌确认弹窗逻辑同样作用于网页端。

## 五、翻谱 MIDI 协议

**专用 loopMIDI 输入端口**，与现有端口物理隔离（NOTE_MAP 60–90、键盘自动化 36–77
都在各自端口，互不冲突）。端口在设置页下拉枚举选择（`_in_devices()` 动态跟随，不硬编码名字）。

音符定义：

| 音符 | 编号 | 含义 |
|---|---|---|
| C2 | 36 | **上一页**命令族：屏幕左半区单/双击（右滑、PageUp 为搁置实现） |
| C#2 | 37 | **下一页**命令族：屏幕右半区单/双击（左滑、PageDown 为搁置实现） |
| C3–A3 | 48–57 | 设备 1–10 |

组合规则：

- 「同一时刻」= 归并窗口（默认约 100ms，按 Cubase 和弦经 loopMIDI 的实际到达时距校准）。
  仅统计 note-on（velocity 0 视为 note-off 忽略）；窗口内设备音符去重。
- 判定矩阵：

| 窗口内音符 | 结果 |
|---|---|
| 恰一个命令音符（36 或 37）+ 至少一个设备音符 | **合法**：向各指定设备发上一页 / 下一页 |
| 命令音符但无设备音符 | 非法：日志报错并忽略 |
| 36 与 37 同时出现 | 非法：日志报错并忽略 |
| 仅设备音符、无命令音符 | 非法：日志报错并忽略 |

- 目标槽位**未配对或设备级停用**：该设备跳过并日志提示，不算非法，其余设备照发。
- 连续翻页：窗口外的重复命令 = 新组合（窗口取小值保证连翻灵敏）。
- 实现沿用 `note_handler` 的稳定性模式：winmm 回调只入队，专用 worker 线程判组合并推送。

## 六、设备配对与设置

- 槽位 1–10。平板网页「翻谱设置」面板：认领空槽（或指定槽）、修改设备名、
  选择翻页方法（单击 / 双击）、设备启用开关、**测试按钮**（当场试翻一页验证链路）。
- 注册时网页上报屏幕分辨率，电脑换算点击坐标并随每次推送下发像素值：
  上一页 = (0.25w, 0.5h)，下一页 = (0.75w, 0.5h)。APP 侧零坐标配置。
- 开关层级（与关系）：
  - 电脑设置页总勾选框：关 = 热点 + HTTP 服务 + 翻谱 MIDI 端口全部停止；
  - 移动端网页的设备级开关：只停该设备的翻谱推送。
- 持久化进 `config.json` 新段（翻谱接收端口全局统一，默认 8766；config 键名 taskerPort 沿用不改）：

```json
"webRemote": {
  "enabled": false,
  "serverPort": 8765,
  "taskerPort": 8766,
  "midiIn": "loopMIDI 端口名",
  "devices": [
    {"slot": 1, "name": "主谱台", "ip": "192.168.137.2",
     "method": "single", "enabled": true, "screen": {"w": 1280, "h": 800}}
  ]
}
```

## 七、自研 APP 推送（Cube 翻谱）

- 平板装自研 APK（网页 `/app.apk` 下载）。APP 内嵌 HTTP 接收器（NanoHTTPD）
  本地监听 8766，前台服务保活；WebView 复用电脑端控制页，显示与遥控同源。
- 电脑对每个目标设备 POST 固定路径 `{"x": 480, "y": 640, "count": 1}`（count=2 即双击，
  两次点击间隔约 100ms）。
- 翻页四通道：tap（单/双击）、swipeL/R（滑动，body 含 x2 终点）、media（dispatchMediaKeyEvent，无需无障碍，兼容蓝牙踏板翻页的谱面 App）；方法在网页按设备选择（method 字段）。使用说明见 docs/移动端APP.md。
- 逐设备独立短超时（约 0.5s），失败记日志、不阻塞其余设备；多设备同刻翻页 = 顺序快发。
- 安全收口：推送目标仅限已配对设备的 `ip:taskerPort` 固定路径，**不做任意 URL 请求**；
  HTTP 服务只绑热点网卡，外部网络不可达。

## 八、网页后台时的稳定性（审查结论）

- **架构性保障**：翻谱链路（MIDI → 本软件 → Cube 翻谱 APP）全程不经浏览器。
  网页被切到后台、被系统冻结甚至被杀掉，翻谱照常工作。
- 浏览器后台的实测影响与对策：Android 冻结后台标签 → 轮询停、状态停更、控制不可用。
  此时用户在看谱，属可接受；回前台立即全量刷新并校准连接徽标。
- 演出使用前提（写入使用说明）：平板保持常亮解锁（锁屏下 Gesture 点击无效）、
  谱面 App 在前台、Cube 翻谱 APP 关闭电池优化（无障碍服务避免被系统回收）。
- 待实测：后台 30 分钟后回前台状态一致性；平板休眠唤醒后翻谱接收端口仍监听；
  双设备同刻翻页的到达时序。
