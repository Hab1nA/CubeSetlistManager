# 移动端遥控与翻谱自动化设计

> 状态：设计定稿，待实现。日期：2026-09-24。
> 网页排版参照 [suckyble/ReaSetlistManager](https://github.com/suckyble/ReaSetlistManager)
> （单 HTML + 轮询 + 底部大按钮走带条 + RESYNC 断线恢复的交互范式）。
> 全程本地通信，不依赖互联网。

## 一、目标与范围

1. **网页遥控**：本软件开启 Windows 移动热点，平板连热点后用浏览器访问控制页
   （播放列表、NOW/NEXT、走带控制，与桌面端同源同权）。
2. **翻谱自动化**：Cubase MIDI 轨经专用 loopMIDI 端口发翻谱信号，本软件解析后
   直接 HTTP 推送到平板自研 APP（Cube Remote），由无障碍手势在屏幕左/右半区做单击/双击/滑动，或发媒体键（蓝牙踏板兼容）完成翻页——按谱面 App 支持情况在网页选翻页方法。

已拍板的范围裁剪：

- **无 WiFi 网卡不做兼容**：检测不到无线网卡即报错并禁用该功能，不给降级路径。
- **翻页方式只做「区域单击/双击」**；模拟 PageUp/Down、左右方向键搁置
  （安卓禁止普通应用向其他应用注入按键，INJECT_EVENTS 属系统级权限）；滑动手势已随自研 APP 支持。

## 二、总体架构

```
平板浏览器 ──HTTP(轮询/命令)──► 内嵌 HTTP 服务（绑热点 IP）
                                   │ self.calls 队列回 Tk 主线程
                                   ▼
                              Cubase 走带 / 切歌 / 全停

Cubase MIDI 轨 ──loopMIDI 翻谱端口──► 专用输入线程（入队 + 组合窗口判组合）
                                   │ 合法组合
                                   ▼
                       逐设备 HTTP POST（平板 IP:翻谱接收端口）
                                   ▼
                       自研 APP 内嵌接收器（8766）→ 无障碍手势/媒体键 → 谱面 App 翻页

热点管理：PowerShell 子进程调 WinRT NetworkOperatorTetheringManager
```

- 新增模块 `web_remote.py`（HTTP 服务、设备表、翻谱推送），热点控制可并入或独立 `hotspot.py`。
- 翻谱数据路径**全程不经过浏览器**——这是后台稳定性（第八节）的架构前提。

## 三、热点管理

- 用 PowerShell 子进程调 WinRT `NetworkOperatorTetheringManager.StartTetheringAsync()`
  （脚本字符串内置在代码里，不新增分发文件）；旧式 `netsh wlan hostednetwork` 不用。
- 启用时序：查 WiFi 能力 → 无网卡 = 弹错误并保持功能关闭 → 开热点 → 读取
  SSID/密码/本机热点 IP → 启动 HTTP 服务并绑定该 IP → 设置页显示 SSID/密码/IP 供平板接入。
- 热点本机 IP 默认 `192.168.137.1`（ICS 默认网段），但**运行时从系统实际查询**，
  不硬编码地址；服务只绑热点网卡，不绑 0.0.0.0。
- 关闭时序反向：停 HTTP 服务 → StopTetheringAsync。
- 防火墙：首次监听 Windows 弹「允许访问」，一次性放行，写入使用注意。
- 已知坑：热点在无客户端一段时间后会被 Windows 自动关闭（演前检查表覆盖）；
  非管理员权限能否开热点待实测（多数环境可以）。

## 四、网页遥控端

- **单文件 HTML，内嵌 CSS/JS**（ReaSetlistManager 的选型：兼容旧平板、离线可用、零构建）。
- 布局：顶部 NOW 大字 + NEXT 次级；中部歌单列表（当前项高亮，歌名永不截断，显示时长）；
  底部 sticky 走带条，大触控目标：播放 / 暂停 / 继续 / 停止 / 回零 / 上一首 / 下一首 / 全停。
- 状态同步：**1 秒轮询**，不做 WebSocket；切歌是关开 .cpr 的秒级操作，期间禁用按钮并显示
  「切换中…」；页面带连接状态徽标，回前台（visibilitychange）立即全量刷新一次，仿 RESYNC。
- 接口（服务端口默认 8765，可配）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 页面本体 |
| GET | `/state` | 快照：NOW/NEXT/歌单/当前索引/切换中/走带状态 |
| POST | `/cmd` | `{action: play\|pause\|resume\|stop\|rewind\|next\|prev\|panic\|switch, index?}` |
| GET | `/devices` | 已配对翻谱设备列表（第六节） |
| POST | `/device/claim` | `{slot?, name, screen:{w,h}（仅诊断）}` 认领槽位 |
| POST | `/device/update` | `{name?, enabled?}` 改名/设备开关（翻页方法在 APP 本机设置） |
| POST | `/device/test` | `{dir: prev\|next}` 对本设备试发一次翻页（调试用） |

- 所有控制动作经既有 `self.calls` 队列回 Tk 主线程执行，复用 `_transport / _next / _prev /
  _panic / _switch`，不在 HTTP 线程碰 Tk；`/state` 数据复用 `_tick_banner` 的 NOW/NEXT 计算。
- 与桌面端一致的行为约束：切歌确认弹窗逻辑同样作用于网页端。

## 五、翻谱 MIDI 协议

**专用 loopMIDI 输入端口**，与现有端口物理隔离（NOTE_MAP 60–90、键盘自动化 36–77
都在各自端口，互不冲突）。端口在设置页下拉枚举选择（`_in_devices()` 动态跟随，不硬编码名字）。

音符定义：

| 音符 | 编号 | 含义 |
|---|---|---|
| C2 | 36 | **上一页**命令族：屏幕左半区单/双击（右滑、PageUp 为搁置实现） |
| C#2 | 37 | **下一页**命令族：屏幕右半区单/双击（左滑、PageDown 为搁置实现） |
| C3–A3 | 48–57 | 设备 1–10 |

组合规则：

- 「同一时刻」= 归并窗口（默认约 100ms，按 Cubase 和弦经 loopMIDI 的实际到达时距校准）。
  仅统计 note-on（velocity 0 视为 note-off 忽略）；窗口内设备音符去重。
- 判定矩阵：

| 窗口内音符 | 结果 |
|---|---|
| 恰一个命令音符（36 或 37）+ 至少一个设备音符 | **合法**：向各指定设备发上一页 / 下一页 |
| 命令音符但无设备音符 | 非法：日志报错并忽略 |
| 36 与 37 同时出现 | 非法：日志报错并忽略 |
| 仅设备音符、无命令音符 | 非法：日志报错并忽略 |

- 目标槽位**未配对或设备级停用**：该设备跳过并日志提示，不算非法，其余设备照发。
- 连续翻页：窗口外的重复命令 = 新组合（窗口取小值保证连翻灵敏）。
- 实现沿用 `note_handler` 的稳定性模式：winmm 回调只入队，专用 worker 线程判组合并推送。

## 六、设备配对与设置

- 槽位 1–10。APP「设置」面板：认领空槽（或指定槽）、修改设备名、设备启用
  开关、**测试按钮**（当场试翻一页验证链路）。翻页方法存 APP 本机（见第七节）。
- 翻页坐标由 APP 按本机屏幕尺寸自行换算（左右半区中点），电脑不感知分辨率；
  认领时上报的分辨率仅作诊断留存。
- 开关层级（与关系）：
  - 电脑设置页总勾选框：关 = 热点 + HTTP 服务 + 翻谱 MIDI 端口全部停止；
  - 移动端网页的设备级开关：只停该设备的翻谱推送。
- 持久化进 `config.json` 新段（翻谱接收端口全局统一，默认 8766；config 键名 taskerPort 沿用不改）：

```json
"webRemote": {
  "enabled": false,
  "serverPort": 8765,
  "taskerPort": 8766,
  "midiIn": "loopMIDI 端口名",
  "devices": [
    {"slot": 1, "name": "主谱台", "ip": "192.168.137.2",
     "enabled": true, "screen": {"w": 1280, "h": 800}}
  ]
}
```

## 七、自研 APP 推送（Cube Remote）

- 平板装自研 APK（网页 `/app.apk` 下载）。APP 内嵌 HTTP 接收器（NanoHTTPD）
  本地监听 8766，前台服务保活；WebView 复用电脑端控制页，显示与遥控同源。
- **语义协议**：电脑对每个目标设备 POST `{"dir": "next"|"prev", "test"?: 1}`
  ——只表达翻页意图；用哪种手势、坐标在哪，由 APP 按**本机设置的翻页方法**
  （tap/double/swipe/media，存 prefs）自行组装执行。电脑端不感知方法与分辨率，
  同一条指令对同网所有设备一致（广播友好），APP 内可随时换方法。
- 翻页四通道：tap（单/双击，点按左右半区中点）、swipe（滑动 220ms，翻书方向）、
  media（dispatchMediaKeyEvent，无需无障碍，兼容蓝牙踏板翻页的谱面 App）。
  使用说明见本文第十二节。
- **低时延机制**：电脑端对每设备维持**持久 HTTP 连接**（连接池，异常弃旧重建
  重试一次，NanoHTTPD keep-alive 退化时自动落到每请求新连接）；APP 前台服务
  持有 **Wi-Fi 高性能锁**（API 29+ FULL_LOW_LATENCY，否则 FULL_HIGH_PERF）
  防省电唤醒把闲置后的第一页拖到秒级。逐设备独立线程推送（PUSH_TIMEOUT 1.5s），
  失败记日志、不阻塞其余设备。
- **耗时埋点**：推送日志带往返 ms；APP 经 /diag 回传 recv→disp（收包到派发）
  与 disp→done（手势执行）两段耗时，冷/热对比可归因。
- 安全收口：推送目标仅限已配对设备的 `ip:taskerPort` 固定路径，**不做任意
  URL 请求**；HTTP 服务只绑热点网卡，外部网络不可达。

## 八、网页后台时的稳定性（审查结论）

- **架构性保障**：翻谱链路（MIDI → 本软件 → Cube Remote）全程不经浏览器。
  网页被切到后台、被系统冻结甚至被杀掉，翻谱照常工作。
- 浏览器后台的实测影响与对策：Android 冻结后台标签 → 轮询停、状态停更、控制不可用。
  此时用户在看谱，属可接受；回前台立即全量刷新并校准连接徽标。
- 演出使用前提（写入使用说明）：平板保持常亮解锁（锁屏下 Gesture 点击无效）、
  谱面 App 在前台、Cube Remote 关闭电池优化（无障碍服务避免被系统回收）。
- 待实测：后台 30 分钟后回前台状态一致性；平板休眠唤醒后翻谱接收端口仍监听；
  双设备同刻翻页的到达时序。

## 十二、Cube Remote 使用说明

> 电脑端有两个页面端口：**8765=浏览器版**（无翻谱功能，右上角「下载 APP」）与
> **APP 连接地址=APP 版**（端口在设置页可改，默认 8767；含「设置」面板）。
> 翻谱命令经 HTTP POST 发到平板 `IP:8766/turn`，body 为**语义指令**
> `{"dir": "next"|"prev", "test"?: 1}`——电脑只说「翻下一页/上一页」，
> 用哪种手势、坐标在哪，由 APP 按**本机设置的翻页方法**自行组装执行
> （电脑端不关心方法与分辨率）。电脑到 APP 使用**持久连接**（复用 TCP，
> 省每次握手），APP 前台服务持有 **Wi-Fi 高性能锁**防省电唤醒，双管齐下
> 压低翻页时延。

### 安装（首次约 5 分钟）

1. 平板连电脑热点，浏览器打开 `http://<电脑热点IP>:8765`，右上角
   **「下载 APP」** 安装（允许未知来源安装）；
2. 打开 APP：连接地址默认已预填（默认端口 8767，可在设置里改），点
   「连接」即进入控制页——与浏览器同款播放列表，但右上角是「设置」；
   已验证接通的地址，之后每次打开 APP 自动直连；
3. 「设置」里认领本机（名字/槽位），可随时「取消登记」；
4. 「设置 → 翻谱设置 → **翻页方法**」按谱面 App 支持选四选一（点按/双击/
   滑动/媒体键，存在本机立即生效）；
5. 按提示 **开启无障碍服务**（顶栏「无障碍」按钮可直达系统设置）——
   点按/滑动翻页靠它；系统会保持屏幕常亮；
6. 按提示 **允许电池优化豁免**（系统确认框点「允许」，一次性）。

APP 启动后自动开启 **前台接收服务**（通知栏显示「翻谱接收中 · 端口 8766」）。

### 无障碍服务保持稳定（重要）

安卓省电机制可能在 APP 退后台后临时解绑无障碍服务。保持稳定的三个措施：

1. 允许本 APP 的**电池优化豁免**（首次启动系统弹窗点「允许」；错过的话
   系统设置 → 应用 → Cube Remote → 电池 → 不受限制）；
2. 在系统无障碍设置里开启**无障碍快捷方式**（下拉快捷面板出现无障碍
   图标，系统会持续强持有服务）；
3. 保留通知栏「翻谱接收中」前台通知（进程被杀后无障碍绑定不会自动恢复）。

### 翻页方法与谱面 App 适配

在 **APP「设置 → 翻谱设置 → 翻页方法」** 里按你谱面 App 的支持情况选
（存在 APP 本机，立即生效；电脑端推送对同网所有设备发同一条语义指令，
各设备按自己的方法执行）：

| 方法 | APP 动作 | 适用 |
|---|---|---|
| 点按 (tap) | 屏幕左/右半区各点一下 | 多数谱面 App 默认支持 |
| 双击 (double) | 同上，双击 | 谱面 App 把「双击」设为翻页时 |
| 滑动 (swipe) | 左/右滑动手势（翻书方向） | 谱面 App 支持滑动翻页时 |
| 媒体键 (media) | 发媒体键「下一曲/上一曲」 | 谱面 App 支持**蓝牙踏板翻页**时；此通道**无需无障碍** |

- 「测试上一页/下一页」会**自动把本 APP 切到后台**再执行手势——先打开
  谱面 App，再回 APP 点测试按钮，看谱面是否翻页；
- 换了翻页方法后记得在谱面 App 侧也对应设置（如开启「点击翻页」「滑动翻页」
  或「蓝牙踏板/键盘翻页」）。

### 常见问题

- **点按/滑动没反应，媒体键有效**：无障碍服务没开或被系统回收——
  顶栏「无障碍」按钮直达系统设置重新开启，并按「无障碍服务保持稳定」
  三措施处理；
- **点击位置不对**：坐标由 APP 按本机屏幕尺寸自动换算（左右半区中点），
  必要时开发者选项开「指针位置」核对落点；
- **翻页时延看哪里**：电脑端日志每次推送带往返 ms（如「翻谱已推送
  （主谱台 next 45ms）」），APP 侧耗时经诊断回传到同一行上下文
  （recv→disp=收包到派发、disp→done=手势执行）；闲置后第一页慢于
  连续翻页属正常（省电唤醒），持续慢再排查；
- **通知栏没有「翻谱接收中」**：给 APP 关闭电池优化、允许自启动；
- **平板换 IP / 换热点**：重新连热点后重新认领（按 IP 幂等，自愈）；
- **真 PageUp/方向键**：安卓不允许普通应用向其他应用注入按键（系统权限
  `INJECT_EVENTS`），用上述四通道替代已覆盖主流谱面 App。
