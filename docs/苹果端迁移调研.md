# 苹果端实现路线调研

调研日期：2026-09-26。
背景：安卓端 Cube Remote（WebView 壳 + 翻谱执行器）已上线，评估向 iOS 迁移的技术路线，
并对 forScore / piaScore 两个 iOS 谱面 App 的翻谱能力做专项调查。

## 一、结论摘要

1. **现有技术路线必须拆成两半评估**：
   - 遥控半场（WebView 壳加载电脑控制页）——迁移容易，iOS 无额外障碍；
   - 翻谱执行半场（无障碍手势注入第三方谱面 App + 媒体键 + 后台常驻）——**在 iOS 上不可行**，
     非越狱设备无公开 API，属系统政策墙而非工程难度，不要在此投入。
2. **推荐路线 B**：iOS 端不写任何 APP。
   遥控 = Safari 打开控制页并"添加到主屏幕"（PWA）；翻谱 = 外包给 forScore 的官方
   网络 MIDI 会话 + MIDI 触发器，电脑端用 rtpMIDI 驱动桥接。安卓侧现有 HTTP /turn
   推送原样保留，两通道并行不互斥。
3. **forScore 是路线 B 的首选载体**：官方手册确认内置 MIDI Network Setup（网络 MIDI 会话）
   和可学习（learn）的 MIDI 翻页触发器。
4. **piaScore（2026-09-26 二轮深挖，产品定位=适应用户自带 App）**：外部通道全枚举后，
   电脑控制唯一候选=Core MIDI 经 midimittr 网络会话旁路（无官方文档，论坛孤例），
   30 分钟真机实验可定性（见 6.3）；HID/URL scheme/伴侣 App 协议全部对电脑关闭。
   电脑端翻谱输出宜做成多通道并行（安卓 HTTP + forScore CC + piaScore 候选）。

## 二、安卓端现状（评估输入）

| 组件 | 实现要点 | 代码位置 |
|---|---|---|
| WebView 壳 | 加载 http://<电脑IP>:8767 控制页，页面代码零改动；自动直连（验证地址）；加载失败回退欢迎页 | mobile/.../MainActivity.kt |
| 翻谱接收 | 前台服务内嵌 NanoHTTPD，:8766 收 POST /turn {dir} | mobile/.../TurnService.kt |
| 翻谱执行 | 无障碍手势（点按/双击/滑动注入第三方谱面 App 左右半区）或 dispatchMediaKeyEvent 媒体键 | TurnService + TurnAccessibilityService.kt |
| 保活/低延迟 | 前台服务 START_STICKY + WifiLock(WIFI_MODE_FULL_LOW_LATENCY) + 电池优化豁免 | TurnService / MainActivity |
| 自动切回 | "使用情况访问"查最近使用 App，翻页测试时自动切回谱面 App | TurnService.lastUsedNonSelfPackage |
| 电脑端推送 | 连接池 HTTP POST /turn；设备表（槽位 1–10）认领制 | web_remote.py push_turn |

## 三、逐项可迁移性（安卓 → iOS）

| 安卓能力 | iOS 等价物 | 结论 |
|---|---|---|
| WebView 加载局域网 HTTP 页 | WKWebView（需 ATS 明文 HTTP 局域网豁免 + 本地网络权限描述） | ✅ 容易 |
| 屏幕常亮 FLAG_KEEP_SCREEN_ON | idleTimerDisabled | ✅ 一行 |
| WifiLock / 电池白名单 / 前台服务 | 无需（前台+亮屏本来不省电）；iOS 无前台服务概念 | ✅ 免做 |
| 内嵌 HTTP 服务器收推送 | 前台可行，但 iOS 后台数秒~数分钟挂起 APP | ⚠️ 模型需反转 |
| **无障碍手势注入第三方 App** | **不存在公开 API** | ❌ 不可迁移 |
| **dispatchMediaKeyEvent 控制其他 App** | **不存在公开 API** | ❌ 不可迁移 |
| 使用情况访问（查前台 App） | 不存在 | ❌ 不可迁移 |
| 启动第三方 App | 仅 URL scheme 且无法控页 | ❌ 无意义 |

结论：**"电脑遥控 iPhone 上的第三方谱面 App 翻页"这个形态在 iOS 是死路**；
翻谱必须改道——要么谱面显示收进自家 WebView（路线 A），要么借谱面 App 自己的
官方遥控通道（路线 B）。

## 四、三条路线对比

| | A：谱面进自家页面 | B：forScore + 网络 MIDI（推荐） | C：PWA 先行验证 |
|---|---|---|---|
| iOS 开发量 | 小 Swift 壳 + 电脑端谱面页 | **零**（纯配置） | **零** |
| Mac / 开发者账号 | 需要（$99/年 或 7 天重签） | **不需要** | **不需要** |
| 翻谱原理 | 网页内容更新，无注入 | MIDI 触发器（forScore 官方能力） | 无翻谱，仅遥控 |
| 谱面 App 灵活性 | 自家渲染，全权在手 | 绑定 forScore | 不涉及 |
| 主要成本 | 电脑端加谱面渲染功能 | forScore 约 $19.99 一次性（国区可能无，需美区账号） | 无 |
| 定位 | 长期终态候选 | 立即可用的完整方案 | 第一步验证手感 |

建议顺序：**C 验证遥控手感 → B 上全链路 → A 视演出体验再决定是否演进**。

## 五、路线 B 落地细节

### 5.1 链路

```
Cubase MIDI 轨 → loopMIDI → 本软件 Python（现有解析）
        │
        ├─ 现有：HTTP POST /turn → 安卓 Cube Remote（保留不动）
        └─ 新增：winmm 发 CC → rtpMIDI 虚拟端口
                    │ RTP-MIDI over WiFi（UDP 5004）
                    ▼
          iPhone forScore（MIDI Network Setup 接收）
                    │ 触发器命中（如 CC102=上一页 CC103=下一页）
                    ▼
                翻页 next / prev
```

遥控侧：iPhone Safari 打开 http://192.168.137.1:8767 → 添加到主屏幕。
Safari 不受 ATS 约束、无本地网络权限弹窗，是零摩擦路径。
网页中"翻页方法/谱面 App 选择/认领槽位"面板对 iOS 设备无意义（安卓无障碍通道专用），
iOS 设备纯当遥控屏。

### 5.2 电脑端（一次性）

1. 安装 Tobias Erichsen 的 **rtpMIDI**（免费，兼容 Apple Network MIDI 协议）。
   装完系统多出一对虚拟 MIDI 端口。
2. rtpMIDI 面板手动添加 iPhone 热点 IP（192.168.137.x）并 Connect。
   **热点网络无 Bonjour 发现服务，自动发现靠不住，必须手填 IP**（与安卓端
   "验证地址直连"同一哲学）。
3. 首次连接 Windows 防火墙弹窗放行 rtpMIDI（专用+公用都勾——热点走公用配置档；
   协议是 UDP 5004）。

### 5.3 iPhone 端（一次性）

1. 购买 forScore（一次性买断，美区 $24.99 / **国区 ¥168 实查有货，无需外区账号**；
   另有订阅制 Pro 功能，翻页用不到。价格快照 2026-09-26，以商店现价为准）。
2. forScore 设置 → Tools → MIDI → **MIDI Network Setup**：启用网络会话，接受电脑连接。
3. forScore 设置 → **Page Turners & Shortcuts**：用"学习"功能把两条消息分别绑定
   上一页/下一页。**建议用 CC 而非音符**（社区实测经验，不易与其他 MIDI 流冲突），
   如 CC102=prev、CC103=next。
4. 打开防自动锁屏设置（演出常亮）。

### 5.4 本软件 Python 接入（十几行）

- `midi_bridge.py` 已是纯 winmm 按端口名开端口，rtpMIDI 虚拟端口对它是普通端口，
  **零新依赖**（python-rtmidi 在本机 Python 3.14 import 即崩的前科更要坚持 winmm 路线）。
- `web_remote.push_turn` 分发处并行加一路：向配置的 rtpMIDI 端口发对应 CC 短消息。
- config.json 增字段：`midiTurnPort`（端口名，不硬编码 rtpMIDI 默认名，读配置跟随——
  与 loopMIDI 端口名单同一原则）、`midiTurnCcPrev` / `midiTurnCcNext`。
- 网页"翻页测试"按钮对 MIDI 通道发一条 test CC 即可等价验证。

### 5.5 风险与注意

| 风险 | 说明 | 对策 |
|---|---|---|
| IP 漂移 | Windows 热点 DHCP 重租可能换 IP | rtpMIDI 有自动重连；IP 变了改会话地址（与安卓 10049 竞态同族，处理思路已熟） |
| 热点重启 | 会话必然断 | 同上；考虑把"rtpMIDI 会话状态"纳入夜测 |
| 触发消息冲突 | 现场其他 MIDI 流（JUNO-DS/AX-09） | 用高位 CC 号（100+）避开常用区 |
| 延迟预期 | 安卓全链路实测 285–496ms（大头是无障碍手势） | MIDI 触发是 forScore 内部响应，预期几十 ms 级，**应优于安卓**，真机复核 |
| forScore 触发器作用域 | 触发器配置是否区分全局/每谱 | 首次配置时确认按全局生效 |

### 5.6 验证顺序（真机一轮一步）

1. **先不写代码**：热点 → 装 rtpMIDI → forScore 建会话 → rtpMIDI 面板手动发一条 CC，
   看 forScore 翻不翻页。此步通过 = 整条路线成立。
2. Python 侧加 MIDI 分支 + 配置项，网页测试按钮联通。
3. Safari 遥控页在 iPhone 过一遍 UI（640px 断点样式直接适用）。

## 六、piaScore 翻谱能力调查

### 6.1 基本

- 免费 + 内购"**Piascore Full Upgrading $5.99**"（App Store 页面核实）；7,000,000+ 用户。
- 官方翻页方式（产品页/App Store 页原文归纳）：AirTurn 蓝牙踏板、"Piascore Air"
  配套 iPhone 遥控 App、面部/手势翻页（wink）、自动滚动/半页翻页、触摸。

### 6.2 外部控制通道全枚举（2026-09-26 二轮深挖）

产品定位修正：**不指定谱面 App，苹果用户自带什么就适配什么**——因此逐通道排查 piaScore
一切可被电脑控制的外部接口：

| 通道 | 状态 | 证据 | 电脑可达性 |
|---|---|---|---|
| **蓝牙 MIDI（BLE / Core MIDI）** | ✅ 实际可用 | 官方帮助原文：保证支持的蓝牙翻页设备=**AirTurn 与 iRig 系列**，其余不保证；piaScore 设置内有「Bluetooth デバイスと接続」（Core MIDI BLE 扫描面板）；iRig BlueBoard=BLE MIDI 设备（默认发 CC， pads A–D，配套 App 可改） | ❌ 电脑无法伪装 BLE MIDI 外设（Windows 无此能力），此通道只属于硬件踏板 |
| **HID 蓝牙键盘**（AirTurn/BlueTurn/PageFlip 模式） | ✅ 实际可用 | iRig BlueTurn 实测博客（bassnote.jp / musica-tonica）：Page Up/Down 等三组键序 | ❌ 电脑无法向 iPhone 伪装蓝牙键盘（非标准配对方向） |
| **WiFi 网络 MIDI（Apple Network MIDI / rtpMIDI）** | ❓ 无官方文档，仅论坛孤例（2017 Piano World：「需要在 iPad 建 virtual network MIDI port」） | piaScore 无 MIDI Network Setup 界面（forScore 有） | ⚠️ **唯一可能的电脑通道**：需 midimittr 类辅助 App 建网络会话+虚拟端口喂给 piaScore，是否被接受待真机验证 |
| URL scheme（piascore://） | ❌ 无公开文档 | 全网搜不到任何官方 URL scheme（forScore 有 forscore:// 并文档化） | ❌ |
| piaScore Air（遥控伴侣 App，240 日元） | 闭源 | 仅 iPhone→iPad 遥控，协议未公开 | ❌ 电脑仿冒=逆向工程，不可维护 |
| HTTP / OSC 远程 API | ❌ 不存在 | 无任何文档/社区痕迹 | ❌ |

关键事实链：piaScore 官方背书的 iRig BlueBoard 发的是 **MIDI CC**（默认 pads A–D 各一条，
可配套 App 重编程）→ **piaScore 至少对某组固定 CC（或学习首个输入）响应翻页**；
M-VAVE/LEKATO 等第三方踏板能用=响应面可能比官方名单宽。但触发消息规格
（具体 CC 号/是否可指定/是否收音符）**官方零文档**。

### 6.3 电脑控制 piaScore 的唯一候选通道与验证实验

途径：电脑 rtpMIDI →（WiFi 热点）→ iPhone **midimittr**（免费，建 Apple 网络 MIDI 会话
并暴露虚拟端口）→ piaScore 若接受任意 Core MIDI 源即可翻页。

**30 分钟定性实验（无需买任何东西）**：
1. iPhone 装 piaScore（免费）+ midimittr（免费），开一份多页 PDF；
2. 电脑装 rtpMIDI，手填 iPhone 热点 IP 连 midimittr 会话；
3. 从电脑依次发**测试消息矩阵**：CC102/103/104/105（BlueBoard 默认族）、
   note 0 / note 1（AirTurn MIDI 惯例族）、Program Change 1/2，每次观察翻页；
4. 全灭则在 piaScore 设置里找「Bluetooth デバイスと接続」类入口看虚拟端口能否手动挂上。

翻页成立 → piaScore 适配与 forScore 走**同一条电脑侧链路**（同一个 rtpMIDI 发送口，
只是消息号矩阵不同，config 里做成可配即"多适配"落点）；
全灭 → piaScore 在电脑控制维度判死，只服务 forScore 类有官方网络 MIDI 的 App。

### 6.4 未决三点（真机验证才能闭）

1. piaScore 是否接受非 BLE 来源的 Core MIDI 输入（虚拟端口/网络会话）——6.3 实验核心；
2. 触发消息规格：固定 CC 族还是"学习首个控制器"（BlueBoard 可重编程 CC 号，
   若 piaScore 是学习式则随便发都行，反而更好适配）；
3. 免费版是否含 MIDI 翻页能力（$5.99 Full Upgrading 的功能边界未公开）。

### 6.5 对比结论与产品视角

| | forScore | piaScore |
|---|---|---|
| 网络 MIDI 官方 UI | ✅ MIDI Network Setup（13.0 手册） | ❌ 无文档，midimittr 旁路待验证 |
| 触发器可配置 | ✅ learn 任意音符/CC | ❓ 疑固定消息族（BlueBoard/AirTurn 惯例） |
| 价格 | $24.99 一次性（国区 ¥168） | 免费（$5.99 全解锁内购） |
| 生态口碑 | iOS 谱面 App 统治级 | 大体量、口碑好 |

**产品视角（适配而非指定）**：电脑端翻谱输出设计为**多通道并行**——安卓 HTTP /turn、
forScore CC 通道、piaScore 候选通道共用同一 rtpMIDI 端口与推送分发点，每通道独立
开关+消息号可配（机制优先，不硬编码）。forScore 通道可立即交付（官方文档背书）；
piaScore 通道完成 6.3 实验后再定去留，验证前标记实验性。

## 七、其它 iOS 谱面 App 外部控制矩阵（2026-09-26 三轮扫描）

扫描标准：**电脑能否不写 iOS 代码、经公开通道驱动其翻页**（网络 MIDI / OSC / URL scheme /
可配置 MIDI 触发）。蓝牙踏板支持不算数——那是给硬件的，电脑伪装不了 HID/BLE 外设。

| App | 电脑控制 | 价格（2026-09-26 实查） | 证据强度 | 通道与备注 |
|---|---|---|---|---|
| **forScore** | ✅ 最佳 | $24.99 一次性（**国区 ¥168 有货**） | 官方文档 | MIDI Network Setup + learn 任意触发消息；另有 forscore:// URL scheme |
| **MobileSheets（iOS 版）** | ✅ 成立 | $15.99 一次性（另有免费 Lite 版） | 真实用户案例 | Options→Global MIDI 建网络 MIDI 会话，**Program Change 触发翻页**（Gig Performer 社区实操帖）；已知瑕疵：会话名被强制为 "iPad"、RTP 断线重连体验一般；安卓本就全功能，iOS 版晚出但 MIDI 齐全 |
| **OnSong** | ✅ 大概率 | 免费 + 订阅/内购（现名 OnSong 2026） | 官方功能在册 | MIDI 触发器 + MIDI Settings 里网络会话配置（社区有 ProPresenter 联动实例）；偏和弦谱/歌词场景，PDF 也能放；MIDI 功能疑似付费层（Premium/订阅） |
| **unrealBook** | ❓ 待核验 | unrealBook Mobile $4.99 一次性 | 强暗示未实证 | 设置里存在 **Network 组**（AirTurn Setup 挂其下）、iRig BlueBoard 实测可用、翻页还能**外发 MIDI**；OSC/网络 MIDI 疑似在册但手册站被 Cloudflare 挡住没验到，需真机翻 Network 设置核验 |
| **Newzik** | ❓ 证据弱 | 免费 + 订阅 | — | "MIDI capable"（收发均有、页面按钮可发 MIDI）、蓝牙踏板 OK；**网络会话无任何证据**；订阅制 |
| **piaScore** | ❓ 唯一缝 | 免费 + $5.99 全解锁内购；Air 遥控另售 240 円 | 见第六节 | midimittr 旁路待 30 分钟实验 |
| **Tomplay** | ❌（也无需） | 免费 + 订阅（14 天试用） | 产品逻辑 | 自动翻页=跟随内置伴奏音轨自成一体，无外部接口；订阅制 |

**架构结论（比单个 App 更重要）**：forScore（learn CC）、MobileSheets（Program Change）、
OnSong（MIDI 触发器）三家的电脑控制**共用同一条链路**——电脑一个 rtpMIDI 出口口，
按目标 App 发不同消息类型即可。多通道翻谱输出（安卓 HTTP + MIDI 矩阵）的一个配置
字段组即可覆盖：
`{"midiTurn": {"port": "<rtpMIDI 端口名>", "targets": {"forscore": {"ccPrev": 102, "ccNext": 103}, "mobilesheets": {"pcPrev": 126, "pcNext": 127}}}}`
（消息号占位示意，真机核验后定值；机制优先，不硬编码。）
