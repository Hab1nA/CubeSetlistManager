# 设计案：合并工程功能（前后端融合）

日期：2026-10-27 ｜ 前置：`docs/预调研-合并工程.md`（格式取证与路线定案）
状态：设计稿，未实现。本文所有"现有机制"均指仓库当前代码（feat/webview-ui 分支）。

---

## 一、功能定位与范围

**一句话**：把播放列表里的多个 .cpr 工程按顺序拼接成一个新工程，自动生成定位点，使演出时单工程 + GOTO 跳曲。

- **输入**：播放列表当前条目（或用户从素材库多选）——都是已按模板统一的工程。
- **输出**：`<工程库根>/合并演出/<演出名>/` 下的一个新工程（.cpr + Audio/ 媒体拷贝 + `setlist_points.json` 定位点 sidecar）。
- **v1 范围**：仅 Cubase .cpr（RIF2/RIFX）；顺序拼接；曲间间隔可设；不合并自动化曲线细节之外的高级对象（和弦轨/编排轨等单例轨仅保留主工程的）。
- **不做**：Studio One .song（v2 可评估——.song 是 ZIP+XML，反而简单）；非模板工程混拼（预检拦截）。

**产品闭环**（这是该功能与本软件的独特契合点）：
素材库（已有）→ 合并生成 → 素材库自动出现新工程 → 定位点已自动配好（`points.py` 全套复用）→ 演出：打开一次合并工程，切歌 = 同工程 GOTO 免重开（`_goto_send` 现有链路），自动推进 = AdvanceWatch 按定位点段计时（现有语义零改动，`set_duration(终点-起点, left=起点)`）。

## 二、后端设计

### 2.1 模块划分（对齐仓库现有分层惯例：纯逻辑与设备/IO 分离）

```
cpr_merge.py          # 对外门面：预检(plan)/执行(run)，纯逻辑，可零设备测试
cpr_merge_reader.py   # RIF2/RIFX 锚点式读端（探针成果产品化）
cpr_merge_model.py    # 歌曲内容模型（tick 域）：轨道/事件/速度/拍号/标记/媒体引用
cpr_merge_writer.py   # XML 时代 .cpr 生成器（≤C12 格式，详见预研报告第五节）
```

- 读端复用探针已证语法：术语 `[BE32 strlen+1][名\0]`（±BOM 后缀）、值标签 1/2/3/4/8、obj0 两形态（紧凑单子/哈希+数量）、`cpr_meta.RE_CYCLE` 定位条。探针脚本（out/）保留作回归测试的对照实现。
- 提取采用**锚点式**而非整文件语法闭合：从 `MFolderTrack/MAudioTrack/MMidiTrack/MTempoTrackEvent/MSignatureTrackEvent/MMarkerTrack/PAudioClip` 等已知类名锚进入子树解析，未知节点跳过（自描述格式支持）。这与 `cpr_meta.py` 的上下文锚定思路同源，只是范围更大。

### 2.2 核心数据流

**骨架-内容模型**（第三轮核查定案，证据见预研报告第九节——模板 79~81% 字节逐字存在于每个已统一工程）：

```
模板骨架（Standard Vo Effect 原样照抄：AppVersion 序言/文档链/轨道表/
          通道插件架构含 GUID/FX 通道；会话态字段取模板值，Cubase 加载重建）
  + 第 1 歌内容（音频事件链/MIDI 链/速度块/拍号/轨自动化，T=0，媒体引用重定向）
  + 第 k 步内容（同上，平移 T_k = Σ(前曲内容终点 + gap)）
  → writer 生成 <名>.cpr（XML 时代格式，Cycle 左右定位条=总时长）
  → 媒体拷贝（按引用收集去重 → Audio/，重写路径、GUID 保留）
  → points.save_points() 写 sidecar（现成函数，原样复用）
  → 【转换步】驱动 Cubase 打开+关闭保存 → XML 自动转 RIF2（见 2.6）
  → 回读校验：cpr_meta.read_locators(新文件) == 预期总时长 ±0.5s
  → 刷新素材库/定位点缓存（进程内直接调，无需 IPC）
```

- **轨道对齐键 = 轨道名字符串**（`Name→String` 值，如 Audio 01~12）：共有轨顺延，歌曲附加轨按名追加。平移量基准 = **内容边界**（实测 4/86 工程内容先于左定位条，アイドル 73.7s / Bad Apple!! 76.5s / SOUL SOLDIER 54.4s / 平行線 32.9s——不能拿定位条当内容起点）。v1 内容终点取 `max(右定位条, 已提取事件终点)`，内容起点取 `min(左定位条, 已提取事件起点)`；gap 默认 2 秒。
- **位置域双轨**：拍号事件 Start/Length 为小节域 f64，事件位置为 tick 域——平移各自域内进行，不跨域换算。

### 2.3 命令面（对齐现有 HTTP 端点惯例）

`web_remote.py` 新增 POST `/mergecmd` + GET `/merge/state`，与 `/plcmd`、`/ptcmd`、`/pedal/learn` 同风格：

| op | 语义 | 返回 |
|---|---|---|
| `plan` | 预检+试算（不动盘） | 每曲 {key, 时长, 起点, 问题} + 总时长 + 媒体统计 |
| `run` | 执行合并（后台线程） | {started} |
| `status` | 轮询进度 | {phase, 曲号/总数, 日志尾} |
| `open_result` | 转换步：驱动 Cubase 开+关保存 | {ok} |

长任务模式照抄踩钉学习（`_pedal_learn_start_web` + `_pedal_learn_poll_web`）：启动置 busy 旗标、轮询取进度；合并期间禁止二次 run（在途门）。

`/state` 快照（`build_snapshot`）增加一个可选字段 `merge`（进行中才出现），前端状态条可提示，不新增轮询通道。

### 2.4 预检清单（plan 必做，run 前复检）

1. **轨道结构指纹（歌间对比）**：各源工程轨道名表（Name→String 值）+ FX 通道名一致——**对比歌与歌，不对比当前模板**（模板会演进；现有工程对齐的是 10-22 版模板，当前模板 10-27 已重存演进）。共有轨顺延、歌曲附加轨（如 Audio 13/14）按名追加；不一致的曲指名拒绝。
2. **采样率**：各工程采样率一致（不一致拒绝；同机同卡实际恒 48k）。
3. **媒体在盘**：每条引用的文件存在（实测 574 条引用在工程目录之外，`Downloads` 等——存在性必须逐条查）。
4. **目标目录**：`合并演出/<名>` 不存在或为空；磁盘余量 ≥ 媒体总大小 × 1.1。
5. **Cubase 状态**：转换步需要 Cubase 可启动（`daw_settings` 现有配置）；合并本身不需要 Cubase 在场。
6. **源文件锁**：源 .cpr 可读即可（只读打开，不管 Cubase 是否开着它）。

### 2.5 产物与定位点自动生成

```
合并演出/
  2026-11-01 场次/            # 演出名=用户输入，默认"合并演出"
    2026-11-01 场次.cpr       # XML 生成 → Cubase 转换为 RIF2
    Audio/                    # 按引用收集拷贝的媒体（去重）
    setlist_points.json       # {"enabled":true, counter:N, points:[…]}
```

定位点：每曲一条，`{id:k, name:<歌名>, start: T_k+左偏移, end: T_k+右定位条}`，`enabled:true`——**合并完成即演出就绪**，用户在编排页看到的合并工程条目展开即各曲。歌名直接用素材库歌名（`display_name` 的「工程 · 点名」显示天然成立）。

`playlist.json` 同步登记：durations 写入总时长（durSrc=manual，转换后可用现有「重新识别」刷新为自动值）。

### 2.6 转换步（XML → RIF2，复用 DawController 现有机器）

XML 产物首次需 Cubase 保存一次转为原生格式。全自动方案——完全复用现有切歌机器：
1. `DawController._open()` CLI 单实例转交打开合并工程（现有 `_wait_open` 等窗口）；
2. `_close()` 发 WM_CLOSE → Cubase 弹保存确认框 → 现有 `_drain` 仿人回车=保存 → **Cubase 以当前版本原生格式写回同一路径**（XML 就地变 RIF2）。
3. `cpr_meta.read_locators` 回读断言（时长匹配 = 转换成功 + 内容完整的第一道校验）。

预研已证 C13 打开 C10.5（XML 时代）工程正常（论坛实证 + exe 内旧解析痕迹），转换步的风险只剩"C15 保存是否就地转格式"——POC P2 第一项验证。若个别工程打开弹未知对话框，`dialog_enter_marks/dialog_log_marks` 现有词表机制承接。**不自动转换也可用**（跳过转换步，XML 工程直接可开可演出，仅时长识别降级），但演出机标准流程建议转换。

### 2.7 安全铁律

- 源工程**只读**，任何路径不写回；产物只进新建目录（重名拒绝，不覆盖）。
- 媒体拷贝用临时名+原子改名；中断清理 `*.tmp` 与未完成目录（下次 plan 检出残留并提示）。
- 合并期间禁用切歌控制器（`ctrl.busy` 同源旗标），防止演出操作打进 Cubase 转换步。
- 失败不留半成品：预检失败零写盘；run 失败删产物目录（可配置保留现场）。

### 2.8 日志与文案

- 日志走 `app.q`（现有 `q.put` → 运行日志卡），每曲一行「已拼接《歌名》（起点 12:34）」，级别沿用前端三档过滤（全部/警告及以上/仅错误）。
- 文案遵照 `docs/UI文案与信息设计规范.md`：动词优先、不带句号、界面词「预检」「生成合并工程」「转换格式」；跨窗文案如需共享进 `ui_text.py`。

## 三、前端设计（webapp/）

### 3.1 入口与信息架构

**入口放「编排」页播放列表列头**——播放列表本身就是"演出单"，合并 = 把演出单固化成一个工程，语义零成本：

```
播放列表 [12]  ⋯        ← pl-more 现有 popover（plMoreMenu）加一项「生成合并工程」
```

- 点击后打开**合并向导弹层**（复用 popover/卡片样式，不做新侧栏页——合并是低频准备动作，不值一个常驻导航位；若日后高频再升级为页面）。
- 主控台/演出模式不动；素材库页无需改动（合并产物自动入库）。

### 3.2 合并向导（两步式，与现有两段确认同气质）

**第一步：参数**
```
┌ 合并工程 ────────────────────────────┐
│ 演出名   [合并演出          ]          │
│ 曲间间隔 [2] 秒                      │
│ ☑ 拷贝媒体文件到合并工程（推荐）      │
│ ☑ 完成后自动转换格式（需关闭 Cubase   │
│   当前工程，约 30 秒）                │
│                                      │
│ 将合并 12 曲 · 预计总长 51:20         │
│ [取消]              [预检]           │
└──────────────────────────────────────┘
```

**第二步：预检结果 → 执行**
```
┌ 预检结果 ────────────────────────────┐
│ ✓ intro          2:14  →  00:00      │
│ ✓ SOUL SOLDIER   4:05  →  02:18      │
│ ⚠ アイドル       3:31  →  06:2?      │
│   工程外媒体 8 个，将一并拷贝          │
│ ✗ 狂言·绮语   轨道结构与模板不一致     │
│                                      │
│ 11/12 可合并，1 曲需处理              │
│ [返回]   [开始合并]（仅可合并曲）      │
└──────────────────────────────────────┘
```
- 行内起点列 = 试算时间表（plan op 返回），让用户合并前就看到演出时间轴——**这是预检的价值证明**。
- ✗ 曲默认剔除并可继续（用户回编排页调整后再来）。

**执行态**：弹层转进度（phase 文案 + 每曲行逐个点亮），完成 toast「合并完成：《xx》已入库，定位点已生成」+ 按钮「去编排查看」。失败显示阶段与首错，产物目录路径给出（便于检查现场）。

### 3.3 组件与状态复用清单（不新造轮子）

| 需求 | 复用 |
|---|---|
| 弹层 | `popover()`（plMoreMenu 同源） |
| 危险/主按钮、两段确认 | `armConfirm()`、`btn primary/danger` |
| 开关 | `tgl`（`setTgl`） |
| 在途防抖 | 现有 `pdRemotePending/ptOnPending/movePend` 同款旗标门 |
| 轻提示 | `toast(msg, kind)` |
| 进度轮询 | `poll()` 主循环捎带 `/merge/state`（merge 进行中才拉，不加常驻轮询） |
| 列表行样式 | `plRow/consoleRow` 的行结构与 `badge/empty-state` |
| 窄窗 | 现有 `x_p2_narrow` 响应式断点（弹层单列） |

新 JS 增量预计 ~200 行（一个向导状态机 + 两个渲染函数 + API 封装 `mergecmd(op, payload)`），index.html 增一个 `<template>` 级弹层骨架。

### 3.4 状态与边界

- 合并进行中：主控台「开始/切歌」不禁用（演出不受影响），但 `/mergecmd run` 二次调用被后端在途门拒绝并 toast。
- 转换步进行中：后端借 `ctrl.busy`，前端 `busy` 徽标自然亮起（现有语义）。
- 移动端/平板（web_remote 平板页）：v1 **不做**合并入口（长任务+文件操作属桌面职能），仅 /state 的 merge 字段让其能显示"正在合并"。

## 四、后续行动安排（2026-10-28 定）

**阶段 0：闸门验证（1~3 天，不写功能代码）**
1. 最小 XML 工程 → C15 真机打开（路线 E 生死判据；样本=手写最小工程或网上样例）。失败 → 回退路线 A/C 重估。
2. 转换步验证：打开后关窗保存 → 文件就地转 RIF2 → cpr_meta 回读可解析。
3. 速度块内部格式解出 + 事件 tick 域定标（对照 DAW 显示时值）。

**0.1 测试件已就位（2026-10-28，out/mergetest/）**——样本搜寻结论：本机 86 cpr+401 bak 全二进制（24 RIFX+62 RIF2 / 134 RIFF+267 RIF2，零 XML）；论坛/StackOverflow/GitHub 均无公开 XML 样本；C15 全安装目录无 `CubaseDocument`/`CString`/`vstTracks` 字面量（XML 工程序列化词汇疑似移除），但活 XML 序列化框架在（UserPreferences.xml 等配置由 C15 亲写，方言 obj class/list/int/member/ID），XML 时代类名（AudioTrack/MarkerTrack/TempoTrack…）全在 exe；官方口径 C15 可开所有旧版工程，用户库迁移链 XML→C13(RIFX)→C15(RIF2) 中 XML 解读可能只存在于 C13。三件对照矩阵（区分「无导入器」vs「XML 写错」）：
- `A_min_xml.cpr`：手写最小 XML 工程（CubaseDocument/Song v2/一 AudioTrack/tempo+signature/timeDisplay，位置 tick 域 PPQ480、tempo=500000µs）；
- `B_corrupt_rif2.cpr`：真 RIF2 头 64KB 截断（坏二进制对照）；
- `C_xml_not_a_project.cpr`：C15 亲写配置 XML 改名（格式正确非工程对照）。
判读：A 开成=路线 E 活；A/B/C 同报「无效」=无导入器（回退直接生成 RIF2）；A 与 C 报错不同类=有导入器但手写方言需迭代。旁证线索：`TicksPerBeat=120`（UserPreferences 实测）、音频事件 f64#2=55125=44100×1.25 整（长度域=采样数）、位置 f64#1=1.201s（秒域，自洽于定位条 54.4s 前有内容）。

**0.1 真机判读结果（2026-10-28）：三件全报「无效的工程文件」→ C15 无 XML 工程导入器，路线 E（生成 XML+C15 官方转换）死亡。** 转向**直接生成 RIF2 二进制**（骨架-内容模型直接服务二进制写入，语法主干已逆向）。验证梯度（每级 C15 真机闸门）：① 读→写往返 byte-equal（writer 基础合法性）→ ② 微改（改一条轨道名）→ ③ 平移（事件+时间偏移）→ ④ 注入（两曲合并成完整工程）。

**REA（Reverse Engineer Anything）评估（2026-10-28）**：GitHub 现象级逆向框架（morluto/rea，npm `rea-agents`，`npx rea-agents setup` 接入 MCP），能力=native 二进制反汇编（Hopper/Ghidra/IDA）+JS/Electron+.NET。对**数据文件格式逆向**（RIF2 语法）无直接帮助——语法主干已用自研探针逆向完成且更精准；**真正的用武之地=当 C15 拒收生成的 RIF2 时，反汇编 Cubase15.exe 的工程加载路径**（CXMLObject/RIF2 读取器），直接读出校验逻辑（必填字段/计数一致性/CRC/对象注册表），定位拒收原因。策略定位：主线自研探针+真机梯度验证先行，REA 为拒收时的重炮预备队（届时需 Ghidra+Java，32 核机器可承受大 exe 分析）。

**第四轮：真机受控实验（2026-10-28 凌晨，用户授权自主作业）**——GUI 自动化管线全通：PowerShell DPI-aware 截图+鼠标轨迹点击+keybd_event 原始键（**SendKeys 组合键不可靠已弃用**）+剪贴板粘贴（**IME 会劫持 SendKeys 输入**）+命令行开工程（单实例弹「激活」确认）。工具集 out/shot.ps1、out/keys.ps1（语法：T等待/K:虚拟键/K2:组合键/KV:粘贴）。**梯度闸门结果**：① byte-equal 往返=无意义（**C15 保存含全局随机 nonce**，同内容两次保存 91% 字节不同，312/312 窗口全变；vo_t5 手术件被完整接受证明**读取器按名字寻址+忽略 nonce**——写时随机读时忽略）；② 等长字节手术闸门 **PASS**（vo_t0.cpr 就地替换轨道名 EXP_NAME_1→2，C15 打开无错、全部 29 轨/插入/游标完好在位）。**格式新发现**（ss_t0 头部解剖）：`MTempoTrackEvent` 值域=[BE32 370]+速度 blob，blob 内含 **f64 秒域锚点序列**（42.857/46.013/48.99/52.812/54.394 递增）——速度图以秒域存储；`MSignatureTrackEvent` 值域=[BE32 3]+28B 定长记录×3（疑似拍域位置 89/230/369 递增，待程序化验证）；**倒序短术语**体系（kcoL=Lock/shtE/iCVT/BuTT/ScoL/sklC）；音频块位置**不是 f64 秒**（全文件仅 3 处 54.396±0.1=定位条×2+TrackVariation×1），**MTrackVariation 里的 54.394428 疑为 SS-UN 块位置**。MAudioEvent 值域 tag6 结构（[i32 1708][f64 1.201][f64 55125][f64 0]）与可见块位置对不上——事件↔part↔轨的容器层级未定，音频块位置字段待定位（候选：MTrackVariation/MAudioPart 值域）。工具教训：对话框按钮点击有目测偏差需逐步截图验证；Hub 的 Qt UIA 不可达；文件对话框用 KV: 粘贴路径最稳。
