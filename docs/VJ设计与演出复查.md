# VJ 设计与演出复查

2026-11-26 复查记录。对象：A/B 双源、默认回落、C2 预载、回零/全停、相关 DAW 与前端交互。
本文区分**当前实现事实、已发现风险、待讨论设计**；文中建议不代表已修复。

## 一、已确认成立的设计基础

- OBS 使用 A/B 两个媒体源。正式切换=隐藏侧设置文件 → 显式 RESTART → 开新侧 → 等 PLAYING → 关旧侧；静音、熄屏、暂停、循环热应用均按对应侧处理。
- OBS 上游 `ffmpeg_source` 在默认 `close_when_inactive=false` 时，隐藏源更新文件会打开媒体；`clear_on_media_end=true` 对应首帧预取路径。**这证明隐藏预载不只是写文件路径，但不等于整段视频已完全解码，最终上屏延迟仍需目标 OBS 与编码实测。**
- 预载只有一个隐藏槽位：后一次预载覆盖前一次，适合“下一条要切换的视频”，不支持同时准备多条。
- VJ 格点击仍切三态：播一遍停 → 循环 → 默认回落。默认全局单值，与同槽循环互斥；紫色描边仅展示预载态，不是另一个点击模式。
- C2 预载与 JUNO 的 C2 移调分属不同 MIDI 口，不天然冲突。VJ 轨不得同时路由到键盘自动化口。
- 当前无右键依赖；已删除的手动预载端点与方法没有残留。

## 二、当前 C2 的真实语义与编写限制

### 当前实现

- C2 note on：记为按住；C2 note off：记为松开。
- worker 处理槽位音符时读取**当时的** C2 状态：按住=预载，松开=正式触发。
- 槽位先到而 C2 未按住时，worker 等 20ms 再判；这不是覆盖所有发送顺序的通用“同拍判定”。
- 预载不换画面；正式触发使用现有统一路径，已预载可省去重复装载。

### 当前可工作的严格写法

1. 先发 C2 note on，最好略早于目标槽位音符；
2. 发目标槽位音符 note on；
3. 在该槽位 note on 之后发 C2 note off；
4. **C2 必须在正式触发点前结束**；
5. 正式触发点只发同一槽位音符，C2 保持松开。

```text
预载：  C2 on ── 槽位 on ── C2 off
触发：                         （间隔）── 同一槽位 on
```

### 当前禁止/不可靠的写法

- **禁止 C2 长音延伸过正式触发音符**：正式触发也会被解释为预载，旧画面继续停留。
- 不要把“C2 与槽位同拍短音”当作可靠写法：若 C2 已松开再到槽位，直接触发而不预载。
- 不要同拍堆多个预载组合：worker 倒积压可能只保留最新音符，隐藏侧也只有一槽。
- 不要在 C2 音符中途停止/跳走：note-off 可能不到达，C2 会保持“按住”，之后槽位全被误判为预载；当前须再发一次完整 C2 on/off 恢复。
- `python midi_bridge.py --send 48` 只发 note on，会留下同样的卡住状态，不能拿它当完整预载测试。

### 赛前必须检查的结果，不只看紫框

- 预载组合到达后，当前画面不切换；
- C2 已结束后，单独槽位触发确实切到目标视频；
- 未预载的触发仍按原方式切换，可能因装载延后，但不应出现单源式黑闪；
- 全停/熄屏后保持黑场，不被在途回落重新点亮；
- 不手动切 OBS 场景，不手改 A/B 源名称、文件和可见性。

## 三、复查发现的风险清单

以下均指本复查时的实现，未宣称已经修复。

### 高优先级

1. **文档中的 C2 长音建议与实现冲突**：正式触发被当成第二次预载。赛前清单旧步骤不得继续照用。
2. **C2 中途停止后可能卡按住**：走带停止/回零/跳走、CC123 没有统一复位钩子。
3. **切 OBS 节目场景后 `_active` 可能陈旧**：首次预载可能把实际可见源隐藏，首次触发可能在可见源上换文件，重新出现黑屏/装载空窗。
4. **熄屏/全停/回零与在途默认回落竞态**：本地状态复核不能撤销已发往 OBS 的动作，黑场后默认视频可能重新上屏。
5. **不同队伍的同名工程会绕过 DAW 活体门**：标题歌名相同即可能被当作当前工程，GOTO 到错误工程。当前规避=全库工程文件名唯一。
6. **Studio One 定位口发送失败后的重开条件仅覆盖 Cubase**：S1 后续跳点可能退化为完整工程切换；S1 的 ACK 文案也误写 MMC Slave。
7. **VJ 设置加载失败仍可能启用保存**：空白表单可能覆盖媒体源名、视频目录、投影与静音设置。

### 状态显示与前端一致性

- 无默认目标时，一遍停视频 ENDED 后 OBS 已黑，页面仍可能显示“播放中”。
- 未开 MTC 时，“未跟随”与在播蓝框并存，视频名却隐藏；`off` 只表示没有走带时钟，不代表视频未播放。
- 默认改到另一格后，旧格的 `row.default` 可能短暂保留，下一次点击看似无变化，待 5 秒重建归一。
- 紫框是本地装载记账，不代表整段解码完成；手动改 OBS 隐藏源不会即时反映，短预载区间也可能被 5 秒轮询漏掉。
- 回零默认视频缺失且 OBS 又断开时，日志可能提前宣称“已熄屏”。
- 手机根地址 `/` 是简化遥控页，完整六页在 `/app`；需要手机操作 VJ/键盘时应使用 `/app`。

### 移调与切歌

- 基线移调显示值是软件目标值，不是琴上回读真值；AX 弯音杆、JUNO 面板操作和发送失败都可能造成分叉。后续提交已加入失败不累计/回滚处理，仍需真机确认显示与硬件一致。
- 新工程窗口出现后若先 Chase CC16/17，切歌收尾的归零可能随后覆盖正确值；该时序需要 Cubase 真机验证，不能仅靠静态代码宣布必现或不存。
- CC 写法：JUNO=CC16、AX=CC17，目标值=64+半音数，段尾写回 64。页面步进只立即向琴发送，不改 DAW 自动化轨；下次定位/起播按时间线覆盖。
- AX 移调本质是弯音钉位，弯音杆可覆盖实际音高。

## 四、当前验收缺口

- pytest 全绿覆盖状态机和协议请求顺序，**不证明真实 OBS 画面无黑闪、C2 全演出时序可靠、JUNO/AX 实际音高与 UI 一致**。
- 必须补做真实链路：预载组合 → C2 松开 → 单独触发；C2 中途停止恢复；切 OBS 场景后首次触发；回落瞬间全停保持黑场；默认视频缺失且 OBS 断连时的失败显示。
- OBS 重启后只保证连接/投影等恢复，不应把“重连自动恢复”理解成当前视频自动重放；当前视频需重新触发或走明确的回落路径。
- 赛前文档中的旧“键盘页录制”“切换工程需确认设置”“VJ 页剩余时间”等步骤需按实际六页 UI 校正，不应照单假验。

## 五、已定设计：C2 预载事务（已实施）

2026-11-26 用户确认采用本节语义，并已按本节完成实现。第二节记录的是实施前的旧行为，
保留作为演进对照；操作演出工程请以本节为准。

### 5.1 目标与兼容边界

把预载与正式上屏合并为一次 C2 按下/松开事务：

- C2 on 开始准备；
- C2 按住期间的槽位音符选择唯一目标并装载到隐藏侧；
- C2 note off 提交该目标到前台；
- A/B 互换后台，下一次在另一侧准备。

**保留旧触发语义**：没有 C2 事务时，槽位音符单独到达仍按当前统一路径直接触发。
已有不使用 C2 的工程无需重写。C2 不再只是“按住修饰”，而是明确的事务边界。

### 5.2 事务状态与规则

每次 C2 事务只需保存：目标槽位/目标文件、隐藏侧、装载状态、事务代际。

| 输入/事件 | 规格行为 |
|---|---|
| C2 on | 开启事务；清除上一事务遗留目标 |
| C2 按住时收到槽位音符（72..101） | 将该视频装载到当前隐藏侧，记为唯一待提交目标，不上屏 |
| 同一事务又收到另一槽位音符 | 后一个覆盖前一个目标与隐藏侧文件；一次事务只提交一个视频 |
| C2 note off 且有目标 | 提交目标：首帧 READY 后交换 A/B 可见性并从头播放 |
| C2 note off 且无目标 | 无操作，不报错 |
| 无 C2 事务时槽位音符单独到达 | 按旧逻辑直接触发；已装载同文件时同值合并不重载 |
| 102 熄屏，无论 C2 是否按住 | 直接熄屏并取消事务，不被修饰 |
| 停止走带、回零、跳走、换工程、全停 | **取消事务、清目标、不提交、不卡键** |

一次 C2 内连续多个槽位不承诺全部预载成功；不得以倒积压方式静默吞掉选择事件。
每个输入事件必须保留到达顺序与其所属事务，不允许 worker 在处理时只读一个全局
`held` 瞬时值来判断历史音符的语义。

### 5.3 两种标准工程写法

**立即确认**（不需要提前量）：

```text
C2 on + 槽位 on → 很快 C2 off → 目标视频上屏
```

**提前准备、准点确认**（A/B 预载的主要价值）：

```text
提前数拍：C2 on + 槽位 on（隐藏侧开始装载）
保持 C2：等待目标时刻
目标时刻：C2 off（首帧 READY 后交换上屏）
```

正式切换的时间锚点由“槽位音符位置”变为“C2 note off 位置”。
工程作者应把 C2 结束点放在要求画面切换的位置，而不是让 C2 越过另一个正式触发语义。

### 5.4 READY、失败与黑场优先级

- 提交时若首帧 READY：交换可见侧并从头播放。
- 仍在装载：保留旧画面，继续等待 READY；不得为追求机械准点先关旧侧。
- 明确装载失败/最终超时：保留旧画面并显示失败，不把黑屏标记为“播放中”。
- 等待 READY 期间发生新事务或取消事件：旧事务失效，不得稍后自行上屏。
- 全停、熄屏、回零具有最高优先级：取消待提交事务，并作废已在切换途中的旧代际；
  **黑场后任何旧事务不得重新打开媒体源。**
- C2 提交与熄屏近乎同时时，按统一动作代际裁决，不能依赖线程碰巧谁先完成。

### 5.5 A/B 与页面状态

- A 前台时只允许准备 B，B 前台时只允许准备 A；交换后职责反转。
- 每次准备/提交前按当前节目场景实况确认活动侧，不能只信连接期 `_active` 缓存。
- 切场景不得把当前可见源当隐藏侧预载；场景内 A/B 规则沿用，不承诺跨场景搬运媒体状态。
- 紫框/副行表示“待提交目标已发起装载”，不等于整段视频完全解码；READY 与否应可区分。
- 提交后隐藏侧变成旧前台视频，不应继续把新目标显示为待提交预载。
- 同一时刻只有一个待提交目标；页面不得暗示多个槽位可同时准备好。

### 5.6 防卡键与调试入口

- 所有停止、取消、换口、换工程路径都要结束事务；禁止 C2 状态永久停留。
- CC123/All Notes Off 只取消事务，不视为提交。
- 调试工具必须能发完整序列：C2 on → 槽位 on → C2 off，以及 C2 on → 取消；
  单独 `--send 48` 不得用于正式预载验收。

### 5.7 实施验收清单

至少覆盖以下自动/真机场景，不能只测“按住预载、松开后另发槽位”的旧路径：

1. C2 on → 槽位 A → C2 off：A 上屏，前台侧交换；
2. 立即交换一次后，反向在另一侧预载 B 并提交：两侧均可反复互换；
3. 提前数拍预载，C2 off 时已 READY，旧画面持续到交换、无空窗；
4. 未 READY 时保留旧画面；失败/超时保留旧画面并报错；
5. C2 on 后无目标直接 off：无操作；
6. 同一事务 A、B 两槽位：只有最后目标可提交，事件不被静默吞掉；
7. 无 C2 的槽位单独触发保持旧行为；
8. C2 按住时 102：直接熄屏并取消事务；
9. 停止/回零/跳走/换工程/全停后，C2 off 或旧 worker 完成都不得复活画面；
10. 切 OBS 节目场景后首次预载/触发不隐藏当前可见源；
11. 无 MTC、OBS 断线重连、默认视频缺失时，页面状态与真实画面一致；
12. 默认回落与 C2 提交同时发生时，按统一代际只保留最新用户意图。

### 5.8 与当前实现的迁移注意

- 当前实现是“按住=预载、松开后再发槽位=触发”；新规格是“note off 直接提交”。
- 不应只把现有 `if held: preload()` 换成 note-off 调 `set_media()`：那仍不能解决
  历史事件乱序、卡键、 READY 失败、黑场复活和切场景等问题。
- 实施需要同时处理事务事件顺序、OBS 动作代际、场景实况校准和前端状态语义；
  页面点击三态与单独槽位触发不需要推翻。
