# Cube Setlist Manager UI 文案审查报告（四轮·文字专项）

- **日期**：2026-09-23
- **审查对象**：四个窗口（setlist_gui 主窗/设置窗、pedal 踩钉窗、kbd_auto 键盘自动化窗、midi_bridge_gui VJ Automator）的全部可见文字：控件标签、按钮、弹窗、状态栏，以及 cubase_ctrl / advance / midi_bridge 打进主窗日志框的运行文案
- **审查方法**：布局代码通读 + 全量字符串清点（含 %r/%s 格式化产物）
- **审查原则**（本次专项由用户提出）：
  1. 文字规范、凝练，不过度冗杂，不把技术细节抛给用户；
  2. 符合用户直觉，可快速理解；
  3. 同类/相似内容采用相似描述法；
  4. 不用符号（→ / = / ←）连接元素（如"时长→"即不合规）；
  5. 重要按钮采用相应突出层级（如绿色"开始"）。

## 总体结论

面向"演出者"的主界面文案基本干净（状态词、确认弹窗、色彩语义都做对了），问题集中在三类：
**① 符号连接词乱用（→ 和 =）；② 开发者视角的技术细节直接抛给用户**
（BS/PC、指针、看门狗、%r 异常格式、英文动作名、耗时指标）；
**③ 同一概念在不同窗口有 2–3 种叫法**。
另发现一条指向不存在按钮的提示文案（按「播放」开始，实际按钮叫「开始」），必须修。
共 33 项：高 6、中 14、低 13。

## 五、重要按钮的突出层级

现有三级正确：**开始=绿底加粗**（主操作）、**全停=红底**（危险/急停）、其余默认；键盘窗 **"录制中…"红字** 状态反馈亦好。缺口两处：

- **设置窗"保存并应用"**：该窗主操作，目前与"取消"同为默认色。建议与"开始"同用绿色主操作级，形成全局规则 **"每个窗口至多一个绿色主操作"**；
- **"清空播放列表"**：破坏性但有确认框兜底，保持默认即可；若加第四级"警示"用红字，不给红底（红底留给"全停"的急停语义）；
- 「写入时长/重新识别」保持默认。可选优化："写入时长"→"保存时长"、"重新识别"→"自动识别"（手动/自动对仗），注意日志中"用「写入时长」手填"等 3 处引用需同步。
