# UI 文案与信息设计规范

2026-10-06 定稿。来源：全软件文案普查（110 处括号、20 对跨窗对照）+ 现代 UX 写作与信息层级调研（NN/g 反馈三分类、Microsoft Writing Style Guide、toast/banner/dialog 通道规则）。配套实现：`ui_text.py`（跨窗复用文案唯一来源）。

## 一、文案六条

1. **状态词分工**：`已停用`=配置关；`未启动`=配了没起来；`未启用`=未激活带原因；`已关闭`=开关态。
2. **空态符号三轨**：`…`进行中（紧贴前字）；`—`不适用；空串=无需显示。
3. **日志句式**：动词开头无句号；错误=`动作未生效:%s` 风格，先因后果。
4. **括号规则**：每句至多一个括号；括号内 ≤10 字短补充、占位符号（如「（未加载工程）」）、动态值注入可留；完整从句改冒号/逗号连写。
5. **标点**：全角标点；中文与英文/数字之间留空格。
6. **跨窗同文**：两个及以上窗口共用的字符串一律进 `ui_text.py` 引用，不复制；单窗文案留现场。

## 二、通道五级路由表（打断程度递增）

| 消息性质 | 通道 | 要求 |
|---|---|---|
| 需要立即决策/不可逆 | 模态确认框 | 恰弹一层，busy 场景警示并入文案 |
| 操作未生效/错误 | 日志＋状态行短句 | 先因后果，给下一步 |
| 持续状态直到解除 | 常驻标签（底栏左/子窗状态行/监控栏） | 位置固定不跳 |
| 操作结果（成功/失败/超时/已清除） | 瞬时状态行 | 空则隐藏或限时回落（kbd 驻留至下次操作；pedal `_set_transient` 5 秒） |
| 过程细节、需追溯 | 仅日志 | 不抢常驻区 |

## 三、页面骨架模板（自上而下）

说明段（可选，一两行）→ 主体内容/配置区 → 瞬时状态行 → 底部操作行（主操作靠右、唯一强调色）。设置段落按使用频率排序：连接类 → 目录类 → 行为类 → 界面类。

## 四、保留定义清单（勿「统一」，均为有意差异）

- **素材库**（界面列表）vs **工程库**（扫描来源）——两个概念，非同文异写。
- 设置页「未监听」（TCP 探测）vs 监控栏「未启动」（监听器生命周期）——两回事。
- NOW/NEXT 英文横幅——演出场景与网页一致。
- 时长双表格式（完整版）vs 单已播（lite）——产品差异。
- 网页走带状态 mini/big 双份——CSS 媒体查询手机/平板各显其一，JS `querySelectorAll(".tstate")` 同步全部实例，是响应式设计不是冗余。
- 「已播|剩余」与进度条并存——演出兜底（进度条远看不清时文字可用）。
- 日志区弹性：日志是窗口主体时伸展（lite 主窗），辅助通道时定高（完整版）。
- 走带跟随占位 `—` 在圆点排除表内（`("-", "", "—")`），不会被加 `●` 前缀。
- 键盘窗守卫句「先在素材库或播放列表选中一首再X」是同窗三连家族（写入时长/识别/键盘自动化），与踩钉窗「未绑定歌曲」状态行不互改。

## 五、子窗排版三规则与悬停帮助（2026-10-06 晚增补）

**排版三规则**：
1. 子窗**窗级说明段零保留**：「用前必知」与机制细节全部进对应控件的悬停提示（就近原则），顶部直接从控件区开始。
2. 控件标签 ≤10 字；操作指导放进「开启后的状态反馈」（如平板转发开启后状态行提示待平板），不在标签里教用法。
3. 底部状态行默认唯一一行（`side="bottom"` 停靠，防后续 pack 次序把底栏挤出窗底）；内容三方优先级：**悬停提示（灰字直显，无前缀标记）＞ 瞬时反馈（5 秒回落）＞ 常驻状态**；辅助状态只在非默认态参与拼接（如平板转发短态，未启用不出现）。状态写法对齐主界面状态格：符号＋短态（如「输入 ❌ ｜ 输出 ❌」），配置键名等调试细节只进悬停提示。

**悬停帮助机制（`dpi.bind_hint`）**：
- `dpi.bind_hint(widget, on_hint, text)`：Enter 显示 / Leave 回落，`add="+"` 不覆盖控件既有绑定；on_hint 由窗实现（`_hint`→`_present` 裁决）。
- 提示文字 ≤30 字，讲机制与用前必知，不重复标签已说的；单窗提示留现场，跨窗复用才进 ui_text.py。
- 无 hover（触屏/演出）零退化：底栏永远显示状态文本。
- 已覆盖：踩钉窗（设备下拉/刷新/两勾选/学习/清除）、键盘窗（乐器与设备下拉/两刷新/录制/触发/清除/底栏行本身——悬停底栏教你怎么读 ✗ 诊断）。主窗/设置页将来照抄机制。
