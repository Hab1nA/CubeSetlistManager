# 设计案：双底座合一（软件内设置项切换 Cubase / Studio One）

日期：2026-10-28 ｜ 状态：已实施（2026-10-31，批1=d3edfef、批2=b24db99）。文中"现有机制"指 10-28 时点代码；实施修正见各节【实施修正】注。后记（2026-11-03）：Cube Automator 自 0.16.0 起停止发行，构建链（spec/预置配置/双安装包）已拆除，源码入口保留——见 CHANGELOG 0.16.0「移除」。

---

## 一、背景与目标

**现状**：Cube Setlist Manager 有两个发布产品——Cubase 版与 Studio One 版。两者**本是同一份代码**：PyInstaller spec 除 exe 名外逐字节一致（S1 spec 注释自证："底座行为差异全走安装时预置的 config.json"），差异只在安装时预置的 config.json 顶层 `"daw"` 键。两个安装包、两个 AppId、两条下载资产，发布/升级/文档全部双份维护。

**目标**：合并为一个产品 **Cube Setlist Manager**，底座（Cubase / Studio One）改为设置页选项，落盘 config，**重启后生效**。

**范围**：
- 收编：Cube Setlist Manager Cubase + Cube Setlist Manager Studio One。
- 不动：Cube Automator Studio One（独立入口 `automator_gui.py`，lite 模式，仍是第三个产品）。

**核心判断**：底座选择已是运行期开关（`setlist_gui.py` 启动读 `"daw"` → `daw_ctrl.FACTS` 选事实表 → `set_active`），全部行为差异集中在 `daw_ctrl.py` 的 CUBASE/STUDIOONE 两个 dict + 少量按 facts 的分支（MMC、定位点），**无任何构建期分叉**。本改动 ≈ 把配置入口从"手改 config.json / 装哪个包"搬到设置页，再删掉一套包装。

## 三、后端设计

### 3.1 设置面新增 `daw` 字段（唯一的功能性后端改动）

**`_settings_get_web`**（设置页 GET `/settings`）新增返回：

```python
"daw": self.daw,                                   # 当前生效底座
"dawName": self.facts["display_name"],             # 当前生效底座显示名
"dawChoices": [{"id": k, "name": f["display_name"]}
               for k, f in daw_ctrl.FACTS.items()],
```

【实施修正】dawChoices 已裁撤——前端底座下拉改静态两 option（贴 st-mode 先例），候选由代码 FACTS 表决定无需动态下发；GET 实际返回 daw/dawActive/dawName 三键。

**`_settings_apply_web`**（保存）按在场检测惯例追加：

```python
if "daw" in p:
    daw = str(p["daw"])
    if daw in daw_ctrl.FACTS and daw != self.daw:
        cfg["daw"] = daw          # 只落盘，不动内存（见 3.2）
```

- 校验：不在 `FACTS` 白名单的值静默忽略（与现有 pint/端口校验同风格，前端下拉本就不会发出非法值）。
- `projectsRoot` / `dawExe` 保存逻辑不动：切底座后旧值随 `dawSettings` 段保留，由 3.3 的回落机制兜底。

### 3.2 生效语义：重启生效，不做运行中热切换

保存时只写 config，**内存里的 facts/ctrl/MTC/mmc_out/素材库一律不动**；保存成功后由前端提示"重启程序后生效"。理由：

- 切底座要换的事实不只一张表：`DawController`、MMC 口、MTC 解码、全库重扫重挂播放列表、窗口标题。抽成可重入流程等于在 4600 行主模块里重写启动时序。
- 切底座是装机级低频操作，重启两秒；现有"端口名称已保存，重启程序后生效"（`_apply_ports` 未就绪路径）已有同款交互先例，用户心智一致。
- `daw_ctrl` 模块级 `ACTIVE` 单进程单底座是既有铁律（文件头注释明写），热切换要连它一起推翻。

不做自动重启进程（自杀重启+互斥体时序，收益为零）。

### 3.3 切换后的首次启动：回落机制已天然覆盖，只补提示

启动链（`__init__` → `_startup`）**零改动**即可按新底座跑起来，因为：

- `daw_settings()`：`dawExe` 指向另一个 DAW 的 exe 时，存在性检查失败 → 回落 `DAW_DEFAULTS[新底座]["exe"]`（自动探测 Program Files 最高版本）。
- `_load_songs()`：按 `facts["song_ext"]`（.cpr/.song）扫 `projectsRoot`。**残留旧库根目录时扫出空库**——不是崩溃，但用户需要重指目录。

补一条启动提示（在 `daw_settings()` 归一后、读配置的调用方）：

```python
if daw_changed:   # config 上次落盘的 daw != 本次启动读到的（进程内记忆即可，或对比 dawExe 归一前后）
    self.q.put("底座已切换为 %s：请到 设置→目录与工程 重设工程库根"
               % self.facts["display_name"])
```

实现取简：`__init__` 里 `self.daw != 上次值` 无法跨进程得知，**改为检测归一结果**——`daw_settings()` 返回的 `projectsRoot` 与新底座 `DAW_DEFAULTS` 不一致且该目录下扫不出当前扩展名的工程时，`_load_songs` 现有"工程库不存在"或空库提示已覆盖。**【实施修正】原拟的"dawExe 回落时附带底座切换语境"提示已裁撤**：回落是静默自愈（探测到的最高版本），空库/路径不存在已有红字覆盖，不新增提示、不引入跨进程状态。

### 3.4 `dawSettings` 拆按底座子段（~~v1 不拆~~ → **v2 反转，2026-11-02 用户指令**）

v1 以"切换低频、拆段省一次浏览"为由保持平铺段。复查实证其代价不可接受：**平铺段 dawExe 残留会把错误 DAW 拉起来**——切到 Studio One 后残留的 Cubase.exe 在本机存在，存在性回落不触发，启动自检直接拉起 Cubase（`daw_settings` docstring 明防的 legacy 事故经共享段重新可达）。v2 拆段根治：

- **schema**：`dawSettings.cubase / .studioone` 各持 `projectsRoot/dawExe`；GET `/settings` 增 `dawSettings`（两底座各自的 root/exe）供前端切换联动换显。
- **读端迁移**（`daw_settings()` 单点）：本底座子段 > （仅当查询底座=config 活跃底座）旧平铺键 > 旧 `cubase` 段（仅 cubase）> `DAW_DEFAULTS`。平铺键只迁给"它实际服役的那个底座"，不外溢给另一底座（否则 Cubase exe 又漏进 studioone 子段=原 bug 换皮）。
- **写端**（`_settings_apply_web`）：root/exe 落入 payload 所选底座的子段（无 daw 键时=当前生效底座）；保存时平铺键被收编进活跃底座子段后清除，`dawSettings` 重构为纯子段结构。
- 前端联动：切换下拉即换显目标底座记忆的 root/exe（字段被手改过则不动，pristine 判断），免"一切换就手动重设"。

### 3.5 单实例互斥名去底座后缀

`_acquire_single_instance()`：`"Local\\CubeSetlistManager-" + daw` → `"Local\\CubeSetlistManager"` 固定名。

- 理由：合一后只有一个安装，互斥名带底座后缀反而出现"新装 + 残留旧装"互不知情双跑双发键的窗口。
- 迁移注意：合并版发布初期，用户机器上可能同时装着旧 Cubase 版（AppId C8F2EC15）与旧 S1 版（AppId CA6676E9）。它们仍用带后缀互斥名，拦不住与新版并跑——发布说明（README/Release）必须写明**装合一版前先卸载两个旧版**。只改一个字符串，不放延迟。

### 3.6 文案硬编码清点

- `webapp/index.html:379`「Cubase 程序」标签 → 前端动态化（见 4.2）。
- `app.js` 路径校验注释仍为「Cubase 程序=文件」——PATH_KIND 校验与底座无关，实况保留不改。
- 后端面向用户的红字已全部走 `facts["display_name"]`（`_ensure_daw`/`_launch_daw`/控制未启动提示），无残留硬编码；`setlist_gui.py:3860` 的 `self.s1` 变量名与语义相反（值=cubase 才为 True），顺手改名为 `self.has_points`，不动行为。
- ~~Tk 老界面（`CUBE_TK=1` 回退路径）~~（该回退入口已于 0.15.0 移除，pywebview 为唯一桌面界面）只读 facts，无独立改动。

## 四、前端设计（webapp 三件套）

### 4.1 设置页新增「底座」选择

位置：**目录与工程**卡片最上（与工程库根/DAW 程序同卡，语义聚拢）：

```html
<div class="field wide"><label for="st-daw">底座</label>
  <select id="st-daw">
    <option value="cubase">Cubase</option>
    <option value="studioone">Studio One</option>
  </select>
</div>
```

【实施修正】原草案把提示行 `<p>` 塞进 `.field` 内——违例（全仓先例 p.dim.sm-txt 一律 `.card` 直下，且 `app.css:609 .card p.dim` 的 margin 叠加 field gap 会出双重间距）；实际实现：note 行放 grid2 之后 card 直下，初始 hidden，由 JS 按落盘/生效值切换显隐并填文案。

`refreshSettings()` 回填 `$("#st-daw").value = d.daw`（落盘值，防保存后 refreshSettings(true) 把用户刚选的底座刷回旧值——后端返回的 daw=落盘值而非内存生效值）。【实施修正】原草案"用 d.dawChoices 填充（同 fillSel 惯例写小循环）"已改静态两 option 写死 HTML（贴 st-mode 先例），fillSel 会注入「无」项/幽灵项/sig 去重三个不该有的行为。【v2 修正】dawName 键裁撤——label 改由前端静态映射 `DAW_LABEL`（选项本就写死两值，随选中值走比随生效值走更贴合"表单编辑的是所选底座"语义）。

### 4.2 动态标签（v2：随所选底座）

label 文案 = `DAW_LABEL[st-daw 选中值] + " 程序"`，change 与 refreshSettings 都刷新。v1 随生效值（dawName）在"已保存待重启"窗口里与表单实际展示的目标底座路径不符，v2 修正。路径校验 `PATH_KIND`（file）与底座无关，不动。

### 4.3 脏跟踪与保存

- `ST_FIELDS` 数组加 `"st-daw"`（快照/脏标记自动纳入）。
- `#st-save` 的 payload 加一行 `daw: $v("#st-daw"),`。
- **切换提醒**：note 行显隐 = 选中值 ≠ 后端生效值 `dawActive`；文案 v2 更新为「底座切换保存并重启程序后生效，工程库与程序路径已按底座分开记忆」。【实施修正】原草案的第二条 toast 已裁撤——note 常驻显隐已覆盖该语义。
- **v2 重启按钮**：底座下拉旁常驻「重启」钮（`.input-row` 内 `btn ghost sm`，同卡浏览钮先例）；终版=单击直发（无二次确认），默认 disabled 灰，仅底座改动态可点并转 danger 红 + 红字 note「重启以实现切换」；点击时表单有未保存编辑先走 `saveSettings()`（端口校验已下沉，非法即中止），`/restart` 判 ok 才 toast「正在重启…」。
- **v2 路径联动**：change 时若 root/exe 字段仍等于原底座记忆值（未被手改），换显为目标底座记忆值并 dispatch input 事件入脏跟踪；被手改过则尊重手改不覆盖。
- 状态卡 `dawAlive` 灯（"DAW 未运行"）与底座无关，不动。

### 4.4 明确不做

- 不做切换前的强制 confirm 弹窗：切底座本身不破坏数据（播放列表失效是重启后库重扫的固有语义，`_load_songs` 现有清失效逻辑照常），页面底部的「应用后生效」提示 + note 行足够。
- 不在主控台/编排页放底座指示。【实施修正】原理由"窗口标题后缀已有"有误——WebView 桌面窗标题是中性名 "Cube Setlist Manager"（webui.py:104），本就无底座后缀，合一后中性名天然正确，无需改动；Tk 路径（已移除）原带 app_suffix 后缀。

## 八、风险与边界

| 风险 | 处置 |
