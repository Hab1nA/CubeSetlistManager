# 设计案：双底座合一（软件内设置项切换 Cubase / Studio One）

日期：2026-10-28 ｜ 状态：设计稿，未实现。本文所有"现有机制"均指仓库当前代码（main 本地，webview 六页 UI 合并后）。

---

## 一、背景与目标

**现状**：Cube Setlist Manager 有两个发布产品——Cubase 版与 Studio One 版。两者**本是同一份代码**：PyInstaller spec 除 exe 名外逐字节一致（S1 spec 注释自证："底座行为差异全走安装时预置的 config.json"），差异只在安装时预置的 config.json 顶层 `"daw"` 键。两个安装包、两个 AppId、两条下载资产，发布/升级/文档全部双份维护。

**目标**：合并为一个产品 **Cube Setlist Manager**，底座（Cubase / Studio One）改为设置页选项，落盘 config，**重启后生效**。

**范围**：
- 收编：Cube Setlist Manager Cubase + Cube Setlist Manager Studio One。
- 不动：Cube Automator Studio One（独立入口 `automator_gui.py`，lite 模式，仍是第三个产品）。

**核心判断**：底座选择已是运行期开关（`setlist_gui.py` 启动读 `"daw"` → `daw_ctrl.FACTS` 选事实表 → `set_active`），全部行为差异集中在 `daw_ctrl.py` 的 CUBASE/STUDIOONE 两个 dict + 少量按 facts 的分支（MMC、定位点），**无任何构建期分叉**。本改动 ≈ 把配置入口从"手改 config.json / 装哪个包"搬到设置页，再删掉一套包装。

## 三、后端设计

### 3.1 设置面新增 `daw` 字段（唯一的功能性后端改动）

**`_settings_get_web`**（设置页 GET `/settings`）新增返回：

```python
"daw": self.daw,                                   # 当前生效底座
"dawName": self.facts["display_name"],             # 当前生效底座显示名
"dawChoices": [{"id": k, "name": f["display_name"]}
               for k, f in daw_ctrl.FACTS.items()],  # 候选从事实表取，前端不硬编码
```

**`_settings_apply_web`**（保存）按在场检测惯例追加：

```python
if "daw" in p:
    daw = str(p["daw"])
    if daw in daw_ctrl.FACTS and daw != self.daw:
        cfg["daw"] = daw          # 只落盘，不动内存（见 3.2）
```

- 校验：不在 `FACTS` 白名单的值静默忽略（与现有 pint/端口校验同风格，前端下拉本就不会发出非法值）。
- `projectsRoot` / `dawExe` 保存逻辑不动：切底座后旧值随 `dawSettings` 段保留，由 3.3 的回落机制兜底。

### 3.2 生效语义：重启生效，不做运行中热切换

保存时只写 config，**内存里的 facts/ctrl/MTC/mmc_out/素材库一律不动**；保存成功后由前端提示"重启程序后生效"。理由：

- 切底座要换的事实不只一张表：`DawController`、MMC 口、MTC 解码、全库重扫重挂播放列表、窗口标题。抽成可重入流程等于在 4600 行主模块里重写启动时序。
- 切底座是装机级低频操作，重启两秒；现有"端口名称已保存，重启程序后生效"（`_apply_ports` 未就绪路径）已有同款交互先例，用户心智一致。
- `daw_ctrl` 模块级 `ACTIVE` 单进程单底座是既有铁律（文件头注释明写），热切换要连它一起推翻。

不做自动重启进程（自杀重启+互斥体时序，收益为零）。

### 3.3 切换后的首次启动：回落机制已天然覆盖，只补提示

启动链（`__init__` → `_startup`）**零改动**即可按新底座跑起来，因为：

- `daw_settings()`：`dawExe` 指向另一个 DAW 的 exe 时，存在性检查失败 → 回落 `DAW_DEFAULTS[新底座]["exe"]`（自动探测 Program Files 最高版本）。
- `_load_songs()`：按 `facts["song_ext"]`（.cpr/.song）扫 `projectsRoot`。**残留旧库根目录时扫出空库**——不是崩溃，但用户需要重指目录。

补一条启动提示（在 `daw_settings()` 归一后、读配置的调用方）：

```python
if daw_changed:   # config 上次落盘的 daw != 本次启动读到的（进程内记忆即可，或对比 dawExe 归一前后）
    self.q.put("底座已切换为 %s：请到 设置→目录与工程 重设工程库根"
               % self.facts["display_name"])
```

实现取简：`__init__` 里 `self.daw != 上次值` 无法跨进程得知，**改为检测归一结果**——`daw_settings()` 返回的 `projectsRoot` 与新底座 `DAW_DEFAULTS` 不一致且该目录下扫不出当前扩展名的工程时，`_load_songs` 现有"工程库不存在"或空库提示已覆盖；真正的增量提示只做一条：`dawExe` 被回落时（`setlist_gui.py:606-608` 现有分支）把消息里的措辞带上"底座已切换"语境。**不在 v1 引入跨进程状态。**

### 3.4 `dawSettings` 平铺段不拆分（v1 决策）

两底座各记一套 `dawSettings.cubase / .studioone` 子段可让来回切换免重设目录，但：切换后库根必然不同（.cpr 库与 .song 库不是同一目录树），拆段只省一次"浏览"点击；代价是老用户配置迁移 + 两处保存逻辑改动。**v1 不拆**，切换一次重设一次。若日后用户真的频繁来回切，`daw_settings()` 单点收口改造，升级路径清晰。

### 3.5 单实例互斥名去底座后缀

`_acquire_single_instance()`：`"Local\\CubeSetlistManager-" + daw` → `"Local\\CubeSetlistManager"` 固定名。

- 理由：合一后只有一个安装，互斥名带底座后缀反而出现"新装 + 残留旧装"互不知情双跑双发键的窗口。
- 迁移注意：合并版发布初期，用户机器上可能同时装着旧 Cubase 版（AppId C8F2EC15）与旧 S1 版（AppId CA6676E9）。它们仍用带后缀互斥名，拦不住与新版并跑——发布说明（README/Release）必须写明**装合一版前先卸载两个旧版**。只改一个字符串，不放延迟。

### 3.6 文案硬编码清点

- `webapp/index.html:379`「Cubase 程序」标签 → 前端动态化（见 4.2）。
- `app.js:2551` 注释「Cubase 程序=文件」顺手改「DAW 程序=文件」。
- 后端面向用户的红字已全部走 `facts["display_name"]`（`_ensure_daw`/`_launch_daw`/控制未启动提示），无残留硬编码；`setlist_gui.py:3860` 的 `self.s1` 变量名与语义相反（值=cubase 才为 True），顺手改名为 `self.has_points`，不动行为。
- Tk 老界面（`CUBE_TK=1` 回退路径）同样只读 facts，无独立改动。

## 四、前端设计（webapp 三件套）

### 4.1 设置页新增「底座」选择

位置：**目录与工程**卡片最上（与工程库根/DAW 程序同卡，语义聚拢）：

```html
<div class="field wide"><label for="st-daw">底座</label>
  <select id="st-daw"></select>
  <p class="dim sm-txt" id="st-daw-note" hidden>切换底座需重启程序生效；切换后请重设工程库根</p>
</div>
```

`refreshSettings()` 用 `d.dawChoices` 填充（同 `fillSel` 惯例，但底座没有"无"项，写个小循环即可）；`$("#st-daw").value = d.daw`。

### 4.2 动态标签

「Cubase 程序」label 改 `<label for="st-exe" id="st-exe-label">`，`refreshSettings` 里按 `d.dawName` 写 `d.dawName + " 程序"`。路径校验 `PATH_KIND`（file）与底座无关，不动。

### 4.3 脏跟踪与保存

- `ST_FIELDS` 数组加 `"st-daw"`（快照/脏标记自动纳入）。
- `#st-save` 的 payload 加一行 `daw: $v("#st-daw"),`。
- **切换提醒**：select change 时显示 `st-daw-note`（对比当前值与 `d.daw` 基线），保存成功 toast 后若 daw 变过，追加第二条 toast「底座已切换为 X，重启程序后生效」（前端 diff，后端返回结构不动）。
- 状态卡 `dawAlive` 灯（"DAW 未运行"）与底座无关，不动。

### 4.4 明确不做

- 不做切换前的强制 confirm 弹窗：切底座本身不破坏数据（播放列表失效是重启后库重扫的固有语义，`_load_songs` 现有清失效逻辑照常），页面底部的「应用后生效」提示 + note 行足够。
- 不在主控台/编排页放底座指示：窗口标题后缀（`app_suffix`）已有。

### 5.3 旧 S1 版用户迁移路径（发布说明口径）

1. 记下旧版 config.json 里的工程库根/端口提示（或直接不管，见下）。
2. 卸载旧 S1 版 → 安装合一版（无预置 config，默认底座=cubase）。
3. 设置页：底座切到 Studio One → 重设工程库根 → 保存 → 重启。
4. 升级不覆盖 config 的机制下，老 Cubase 版用户原地升级零操作。

config/playlist 数据不入包（安装器既有口径），卸载旧版不丢用户数据文件所在目录的清理由用户自决（文档提示一句）。

### 6.2 真机验收清单

1. cubase 底座启动 → 设置页显示"底座: Cubase"，标签"Cubase 程序"。

## 九、明确不做（YAGNI 边界）

- 运行中热切换底座（3.2 论证）。
- `dawSettings` 按底座拆子段（3.4，留升级路径）。
- 自动重启进程。
- Cube Automator 并入或其 Cubase 化（独立产品线不动）。
- 主控台页底座徽标/指示（窗口标题已有后缀）。
