- 技术栈已落地：pywebview 6.x + WebView2 桌面壳；Tk 业务栈子线程化（`webui.py`），

- 8 页功能面已迁全（主控台/编排/定位点/踩钉/键盘/VJ/设置/日志）；CDP 逐页截图（`out/shot_pages.py`）无 JS 错误。
- `CUBE_TK=1` 可回退旧 Tk 界面；打包态 `/app` 资源路径已处理。

**评审方法**：通读三件套代码 → 实跑 webui 用 CDP 截取 8 页真实截图 → 逐页视觉评审 →
对照旧 Tk 界面（`setlist_gui.py` 等）功能面 → 核对 `web_remote.py` 后端端点能力。

**总评**：骨架方向正确（8 页导航、状态条、设计 token 雏形），但处于「功能挂上去」
而非「设计过」的状态。全部 CSS 没有一条 `transition`，绝大多数按钮没有 hover/active 态
——这是「呆」的直接原因。另有一个 P0 交互陷阱（演出模式进去出不来）。

## 三、设计系统（先立这个，成本最低收益最大）

### 3.1 Token

在现有 `:root` 上扩一组，之后所有组件只用 token：

```css
:root {
  /* 间距阶（4 的倍数） */
  --s1:4px; --s2:8px; --s3:12px; --s4:16px; --s6:24px; --s8:32px;
  /* 字阶（演出大字单列一档） */
  --f-xs:12px; --f-sm:13px; --f-md:15px; --f-lg:18px;
  --f-xl:22px; --f-2xl:28px; --f-now:42px; --f-show:72px;
  /* surface 层级：0=页面底 1=卡片 2=悬停 3=选中/浮起 */
  --sur-0:#101418; --sur-1:#171c22; --sur-2:#1f262e; --sur-3:#232b34;
  /* 既有语义色沿用：--ok --warn --err --accent --line --fg --dim */
  /* 动效 token */
  --t-fast:120ms; --t-mid:200ms; --ease:cubic-bezier(.2,.7,.3,1);
}
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition:none!important; animation:none!important; }
}
```

字体栈补齐：`"Microsoft YaHei", "PingFang SC", system-ui, sans-serif`；时间码一律
`font-variant-numeric: tabular-nums`。

### 3.2 组件清单（类名即组件边界——平板/APP 复用的前提）

| 组件 | 变体 | 说明 |
|---|---|---|
| `btn` | primary / ghost / danger / icon；sm / md / lg | 统一 hover/active/focus/disabled 态；lg ≥48px 高（演出可点性） |
| `card` | — | sur-1 底 + line 边 + --s4 内边距，页面分区的基本砖 |
| `row` | list 行 | 三态：played（置灰+✓）/ current（高亮+左色条+播放指示）/ normal |
| `field` | — | **label 上置**的现代表单：label 小字灰 + 输入框占整行 |
| `switch` | — | checkbox 换拨杆（行为设置类专用） |
| `tag` | — | 团队名等枚举标牌，替代 `[文本]` 裸写 |
| `toast` | ok / err | 右上滑入自动消失，替代全部 alert |
| `empty-state` | — | 图标+一句话+引导动作 |
| `tooltip` | — | 状态灯、图标钮的悬浮详情 |

对齐遵循 8px 网格；页面内容区宽窗下 `max-width: 960px`（主控台除外）。

## 四、逐页改进方案

### 4.1 主控台 = 演出驾驶舱

- **Hero 区**：NOW 卡片化（card + 大内边距）成为唯一视觉锚点；状态 chip（播放中/已暂停）；
  时间改「已播 3:12 · 剩余 1:45」带标签，废除 `0:00 | 0:00`。
- **进度条**：加粗到 10-12px、圆角、`width` 过渡（见动效 #3）。
- **走带重组**：
  - 主操作 = **一个智能按钮**按 tstate 切形态：stopped→「▶ 开始」、playing→「⏸ 暂停」、
    paused→「▷ 继续」、busy→「切换中…」禁用；
  - 次级 = 回零/上一首/下一首，图标钮；
  - 危险 = 「■ 全停」隔离到右侧、红描边，与主操作拉开物理距离。
- **曲目列表三态**：已播置灰 ✓ / 当前高亮+左色条+播放指示动画 / 未播 normal；
  行 hover 显示「切歌」幽灵按钮（双击保留，补可发现性）。
- **定位点快跳 chips**：当前曲目的定位点横排 chips，点击即 GOTO（后端能力已在，旧版有同款）。
- **空状态**：无工程时图标+「未打开工程」+引导按钮，替代一行灰字。
- **NEXT** 次级卡片带「切到这首」按钮。

### 4.2 编排

- 列头工具条：搜索框（过滤素材库+播放列表）+ 计数 badge + 「⋯」菜单（收编清空/防误触）。
- 素材库行：团队用 `tag`；hover 时 ＋ 变实色；已在播放列表的曲目标记 badge 防重复加。
- 播放列表：**HTML5 原生拖拽排序**（不引库）：拖拽手柄 ⠿ + 插入位置指示线 + 拖起行半透明；
  ↑↓ 移除，删除入 ⋯ 菜单 + **两段式确认**（点一次变「确认移除？」3s 超时回弹）替代 confirm。
- 空状态：「从左侧素材库点 ＋ 加入曲目」。
- 窄窗（< 900px）双列折叠为单列 tab。
- 列表差量更新（见 §7）。

### 4.3 定位点 = master-detail

- 左列表（名称+时码段+启用数）/ 右编辑卡双栏；选中行与表单有视觉联动。
- 时码输入：`inputmode=numeric` + **即时校验**（红框+原因文案，保存按钮随校验禁用）
  ——根治静默失败；格式提示常驻 placeholder。
- 编辑卡动作分层：「保存」主钮 / 「跳到这点」（GOTO 预览）/ 「删除」danger 入 ⋯ 菜单。
- **只读时间轴缩略条**：一条水平条显示当前曲目时长与各定位点段落分布，一眼看布局。
- 工程选择器带 ✓ badge；启用开关用 `switch` 放列头右侧。

### 4.4 踩钉

- 顶部状态卡：连接态大字 + **最近踩钉事件闪烁指示**（学习/测试时的关键反馈）。
- 表单分组卡：基本 / 手势 / 高级（折叠）。
- 单踩/双踩两张「手势→动作」可视化卡，替代挤一行的 select。

### 4.5 键盘

- JUNO / AX-09 两张端口卡（label 上置）。
- 音色槽升级为**网格卡片**：音名（仓内口径 C4=60，JUNO 60-69=C4-A4，AX 72-77）、
  PC 值大字、MSB/LSB 副文本、未配置虚线占位；点击弹 **popover 行内表单**替代 prompt 链。
- 移调：stepper 控件（− 值 +）+ 当前值大字 + 「重置」。
- 接 `/kbdtest`：实时按键测试区（显示收到的音符/力度），学习利器。

### 4.6 VJ

- 状态卡：OBS 连接 / 媒体源在线（接真实状态，替换写死 warn）。
- 即时操作区：黑场/恢复（后端无对应端点则列 P2 补端点）。
- 表单分组卡。

### 4.7 设置

- 四张分组卡：联动端口 / 行为 / 目录与工程 / 移动端遥控；卡内两列、label 上置。
- **脏标记 + 保存**：标题栏「● 未保存」，未改动时保存钮禁用。
- 端口数字输入统一宽；路径输入带存在性校验图标。
- 移动端遥控卡内：APP 连接地址大字可点复制（二维码 P2，用无依赖小段 JS 生成）。

### 4.8 日志

- 工具条：级别过滤（全部/错误）+ 自动滚动开关 + 清空 + 复制。
- 行着色（级别色左条）、时间列固定宽。
- **增量 append** 替代全量 innerHTML（顺带修好文本可选中复制）。

### 4.9 侧边栏与状态条

- 侧边栏三组分区、200px、16px 手写 stroke SVG 图标（8 个，不引图标库）：
  - **演出**：主控台
  - **准备**：编排 / 定位点 / 踩钉 / 键盘 / VJ
  - **系统**（沉底）：设置 / 日志
- 当前项：accent 左指示条 + 背景提亮 + 图标着色。
- 底部：演出模式大按钮（accent 填充）+ 版本号。
- 状态条灯位：hover tooltip 显示详情；点击跳转对应设置页（状态→动作映射）。

## 五、动效规范（少量、克制、有原则）

**原则**：动效只服务三件事——①状态变化反馈 ②空间关系（页面从哪来到哪去）
③持续过程（进度/播放）。**不做装饰动画**。时长 120-240ms ease-out。
全部纯 CSS transition/animation，无 JS 动画库。尊重 `prefers-reduced-motion`。

**节拍约束**：/state 轮询周期 500ms 是全局节拍器，动效时长避开 500ms 及其谐波
（用 120/160/200/240/300）防拍频感；进度条例外，500ms linear 与轮询咬合。

| # | 处 | 做法 |
|---|---|---|
| 1 | 全局按钮 | hover 背景 120ms + active `scale(.97)` 60ms——**修掉「呆」的主刀，一行通配** |
| 2 | 页面切换 | 进入淡入+上移 8px（160ms）；无退出动画保持瞬时响应 |
| 3 | 进度条 | `width` transition 500ms linear，视觉连续不跳格 |
| 4 | 状态灯 | 颜色 300ms；err 落位时脉冲 2 次 |
| 5 | Toast | 右上滑入/自动滑出，替代全部 alert |
| 6 | 列表行 | 编排页增删行 fade+slide 120ms（行数少，无需 FLIP） |
| 7 | 演出模式 | 整屏 opacity+scale 200ms 进出（配合 P0 退出修复） |
| 8 | 当前播放行 | 左侧 3 根小跳动条（音乐软件「正在播放」标准语汇，1.2s 循环、幅度小） |
| 9 | 焦点环 | `:focus-visible` ring + 过渡，键盘可用 |

**刻意不做**：侧边栏滑出动画、卡片 3D、视差、大队列 stagger——演出软件要确定感，不要炫。

## 六、反模式整改对照

| 现状 | 改为 |
|---|---|
| `alert()` 保存结果 ×4 | Toast |
| `confirm()` 删除/清空 | 两段式确认按钮 / ⋯ 菜单 + undo toast |

| `0:00 \| 0:00` | 「已播 x · 剩余 y」 |
| 双击切歌无提示 | 行 hover 幽灵按钮 + 空状态引导 |

## 附录 A：技术栈定案要点（承接原调研，2026-10-20 定案）

- **定案**：pywebview（WebView2）+ Web 前端，桌面窗/平板遥控/安卓 APP 收敛为一个 UI 栈。
  理由排序：①能力上限——侧边栏/层级/响应式/动画是 Web 默认态；②双端收敛砍掉双 UI 同步的
  永续成本；③迁移成本反低于 Qt——web_remote 页面资产、HTTP 端点、状态推送链路全是现成的。
- **淘汰记录**：ttk（天花板已撞）、CustomTkinter/ttkbootstrap（低维护+本质仍 Tk）、
  Flet（表单列表型控件弱+体积）、DearPyGui（CJK 与表单弱）、Kivy（桌面观感差）、
  NiceGUI（引入 asyncio 心智模型，观察项）、Electron/Tauri（双运行时过度）。
- **逃生门**：现场机暴露 WebView2 硬伤（焦点/置顶/全屏/渲染/停摆复发）则改选 PySide6
  （需当场验证 Python 3.14 wheel）。
- **迁移进度**：P0 PoC 过门禁（pywebview 起窗/JS 桥/CDP 渲染帧取证）→ P1 骨架 →
  8 页功能迁全 → 打包路径修复（81c0828）。剩余 = 本文的设计质量与打磨路线。
