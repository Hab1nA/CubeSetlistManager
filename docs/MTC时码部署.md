# MTC 时码部署说明

0.13.0 起走带同步（进度/三态/自动推进/视频跟随）的数据源是 **MIDI 时码
（MTC）绝对位置**，不再是 MIDI 时钟脉冲。每个演出工程（建议直接改工程
模板）需要一次性的设置：

## DAW 侧设置

**Cubase**：运行控制 → 工程同步设置 → 「目标」页 → **MIDI 时码目标**
勾选时码端口（如 `VJ Automation`）→ OK。
（原「MIDI 时钟目标」可以保留不动——应用只把 F8 当诊断计数，不参与
同步；但只开时钟不开时码的工程应用全盲。）

**Studio One**：歌曲选项 → 同步 → MIDI 时码输出勾选时码端口。

建议改完后保存进工程模板，后续新工程零配置。

## 应用侧设置

设置页「**时码端口名称**」选同一端口（config 键名仍为 `clockPortHint`，
旧配置无需迁移）。留空=时码监听停用，走带三态/已播/自动推进/停止键全部
不可用。

## 行为速查

| 场景 | 表现 |
| --- | --- |
| 播放中 | 四分之一帧流（30fps 工程 ≈ 每秒 15 次完整位置），进度/剩余实时跟随播放头 |
| 拖播放头/跳 marker（播放中或暂停后） | 位置立即跟跳（全帧驱动），无需回零或切歌复位 |
| 暂停态把光标拖到曲尾 | 进度显示跟随，但**不会**触发切歌——推进只认「用播放真实到达过曲尾」 |
| 暂停/停止 | QF 断流 0.25s → 三态「已暂停」，已播保持真实停点 |
| 回零 | 应用主动纪元复位：立即显示 0:00，不等下一条时码 |
| 全停 | 发停止键 → 2 秒后核验时码确已停（未停则红字提示）；进度保持真值、本曲不再自动推进 |
| 播到定位条右端 | Cubase 不会自己停，应用在位置≥时长时发停止键（3 秒重试至多 3 次），断流且 ≥99% 自动切下一首 |
| 只见 F8（时码没开） | 日志一次性提示「请在工程同步设置勾选 MTC 时码输出」 |

## 真机取证（2026-10-19，Cubase 15 / Win11 26H2 / loopMIDI）

- QF 30fps 工程实测 123 条/秒、类型 0→7 严格循环，位置与播放头墙钟锁定；
- 停止/定位时各补发一条全帧 `F0 7F 7F 01 01 … F7`，winmm 单缓冲整帧投递，
  解析无缺字节；
- F8 与时码同口并行互不干扰（412:1234 计数比）。

取证工具：`py -u tools/probe_mtc.py <端口名子串> <秒数>`（`--selftest`
离线自检）。

## 定位点（新增，仅 Cubase 底座）

定位点把一个工程切成若干段式条目（[起点, 终点] 绝对时码），启用后素材库
与播放列表里该工程原位展开为「工程名 · 定位点N」。切到定位点 = 同工程免
重开（停走带 → MMC GOTO 到起点 → 按需播放），跨工程自动开关工程后补定位；
播到段终点照常自动推进（判定口径与整曲一致）。

数据存工程目录 `setlist_points.json`：停用只翻 `enabled` 不删定义；播放
列表删点条目=仅移出节目单；删定义只在定位点设置窗里删，删光自动停用。

**真机前提（一次性，建议进工程模板）**：运行控制 → 工程同步设置 →
「机器控制」页勾选 **MMC Slave Active** 并选同一时码端口；Device ID 保持
127（响应所有 ID）。MMC 与 MTC 时码输出完全解耦，互不影响。

定位通道为 MMC GOTO（`F0 7F 7F 06 44 06 01 …`，SMPTE 绝对时间，30fps），
经与时码相同的虚拟口外发；应用侧 GOTO 后 1.2 秒内时码无变化会红字提示
「工程未响应定位」（时码从未在场的会话不误报）。播放中定位统一步骤为先
停后定位——**真机实锤：播放中 GOTO 被忽略**（光标线性推进不跳变），
「先停后定位」是必需而非保守选择。

真机取证（2026-10-19，Cubase 15 / Win11 26H2 / loopMIDI）：停止态 GOTO
发送后 **+0.01 秒** 全帧回流、位置精确命中目标（1:00 与 2:00 双点验证）；
播放中同帧无效果。ACK 机制与该行为天然匹配。

取证工具：`py -u tools/probe_mmc_goto.py <输出口子串> 分:秒 [秒数]`
（`--selftest` 离线自检）——发 GOTO 后监听同口全帧，位置跳到目标即通过。
